# Руководство

Здесь собрано то, что нужно для начала: как установить программу, как подключиться к роутеру, что включить на самом роутере и что делать, если не получается. Описаний каждого окна нет. Меню и поля программа читает у роутера, а смысл настроек объясняют производители; для MikroTik это документация RouterOS. О проекте в целом написано в [README.ru.md](README.ru.md).

**English:** [GUIDE.md](GUIDE.md)

## Установка

### Windows

Запустите установщик (`windows-setup.exe`) или переносной файл (`windows-portable.exe`, установки не требует). Если у файла нет подписи издателя, Windows покажет окно «Система Windows защитила ваш компьютер»: нажмите «Подробнее», затем «Выполнить в любом случае».

Переносной файл при первом запуске распаковывается в `%LOCALAPPDATA%\NetworkHelm\portable\<версия>` (около 200 МБ) и хранит настройки в папке `NetworkHelm data` рядом с собой. Если установщик или переносной файл пишет, что программа не поддерживает эту версию Windows, у вас Windows 7, 8 или 8.1. Для них есть файлы с пометкой `legacy`.

### macOS

Откройте DMG и перетащите NetworkHelm в «Программы». Если программа не подписана Apple, при первом запуске macOS откажется её открыть. Откройте «Системные настройки», «Конфиденциальность и безопасность», найдите сообщение о NetworkHelm и нажмите «Всё равно открыть». Когда macOS спросит про доступ к локальной сети, разрешите его: без этого программа не достанет роутеры вашей сети.

### Linux

DEB и RPM ставятся менеджером пакетов:

```bash
sudo apt install ./NetworkHelm-<версия>-linux-amd64.deb
sudo dnf install ./NetworkHelm-<версия>-linux-x86_64.rpm
```

AppImage не ставится: сделайте файл исполняемым (`chmod +x`) и запустите. Он монтируется через FUSE и ждёт `fusermount` из пакета `fuse3` или `fuse`; без FUSE запускайте его с ключом `--appimage-extract-and-run`.

### Android

Скачайте APK и откройте его, Android спросит разрешение на установку из этого источника. При первом подключении разрешите программе «Устройства поблизости». Без этого Android не пускает её в локальную сеть, и вместо входа вы увидите сообщение «Android не пускает NetworkHelm в локальную сеть».

### iOS

Готового приложения нет, есть проект Xcode. На Mac с Xcode один раз выполните `tools/ios/build-ssh.sh`, затем откройте `app/iosApp` и соберите приложение на своё устройство.

Список соседей, MAC-Telnet и Wake-on-LAN работают широковещательными пакетами, а их iOS разрешает приложению отправлять и принимать только с разрешением multicast, которое Apple выдаёт по заявке. Пока его у приложения нет, вкладка «Соседи», вход по MAC-адресу и Wake-on-LAN на iOS скрыты. Когда разрешение есть, для MAC-Telnet нужен ещё MAC-адрес самого устройства, и окно подключения его просит: iOS не сообщает его приложениям, а роутер отвечает на адрес, который назвал клиент. Это «Адрес Wi-Fi» в Настройках → Wi-Fi → (i) у сети; с частным адресом он у каждой сети свой. Таблица ARP приложениям закрыта, поэтому сканер сети не показывает там MAC-адрес и производителя. Язык приложения задаётся в Настройках → NetworkHelm → Язык.

## Первое подключение

При запуске открывается окно подключения. Поля в нём такие:

| Поле | Что вписать |
| --- | --- |
| Адрес | имя или IP-адрес роутера; порт добавляют через двоеточие, если он нестандартный |
| Платформа | тип устройства; программа определяет его сама и пишет рядом «определена сама» |
| Протокол | способ подключения; серым отмечены порты, которые не ответили |
| Порт | менять нужно, только если служба на роутере слушает нестандартный порт |
| Пользователь, Пароль | учётная запись на роутере |
| Запомнить пароль | сохранить пароль в защищённом хранилище системы |
| Группа, Комментарий | для порядка в списке сохранённых роутеров |
| Через роутер | подключиться через SSH другого сохранённого роутера, если нужный недоступен напрямую |

Как только вы вписали адрес, программа почти сразу проверяет, какие порты на роутере отвечают. Она только пробует открыть соединение и читает приветствие, не входя в роутер; по ответам определяет тип устройства и выбирает протокол. Выбор можно поменять руками. У роутера с защитой от подбора паролей такая проверка может сойти за попытку входа, и он заблокирует ваш адрес. Тогда выключите её в «Настройках»: пункт «Распознавать устройство и проверять, какие протоколы отвечают, пока вводится адрес».

Нажмите «Подключиться». Кнопка «Сохранить» кладёт роутер в список на вкладке «Сохранённые», при следующем запуске его достаточно выбрать там: щелчок заполняет форму, двойной щелчок подключает. Группа каждого роутера стоит в своей колонке, а галочка «Группами» рядом с кнопкой «Импорт» раскладывает роутеры под заголовки групп, роутеры без группы — последними; щелчок по заголовку сворачивает и разворачивает группу, и программа помнит и то и другое до следующего запуска. Вкладка «Соседи» показывает MikroTik, которые объявляют себя в вашей сети. Они делают это раз в 30–60 секунд, кнопка «Обновить» просит их ответить сразу. В окне шириной от 960 dp форма и списки стоят рядом на всю высоту окна; кнопка справа от вкладок уносит списки под форму и обратно. Под формой высоту между ними делит полоса: её можно перетащить, двойной щелчок возвращает форме её собственную высоту.

Если подключение идёт по протоколу без шифрования (API на порту 8728, HTTP, SNMP v2c), под полями появится предупреждение, а в главном окне метка «Без шифрования». Пароль и все данные тогда идут по сети открытым текстом, так что работать в таком режиме стоит только в доверенной сети.

Чтобы открыть конфигурацию без роутера, нажмите «Открыть файл конфигурации» или перетащите файл на окно подключения: подойдёт `/export` RouterOS, бэкап OpenWrt, файл UCI или running-config Keenetic (вывод `show running-config` или файл startup-config из веб-интерфейса).

## Подготовка роутера

Программа ходит к роутеру через службы, которые на нём уже есть. Если нужная служба выключена или закрыта файрволом, подключиться не получится, и программа напишет, какой порт не отвечает.

### MikroTik RouterOS

Службы видны в WinBox и в консоли: `/ip service print`. Подойдёт любая из них:

| Способ | Порт | Замечания |
| --- | --- | --- |
| TCP 8291 (порт WinBox) | 8291 | через этот порт работает весь интерфейс, ни API, ни REST, ни SSH не нужны; программа выбирает его первым, если порт отвечает; вход по этому порту не работает на RouterOS 6.42, там выберите API |
| API-SSL | 8729 | шифруется; нужен сертификат: без него RouterOS отвечает анонимным TLS, которым программа не пользуется |
| API | 8728 | без шифрования |
| REST по HTTPS и HTTP | 443 и 80 | только RouterOS 7.1 и новее, службы `www-ssl` и `www` |
| MAC-Telnet | UDP 20561 | для роутера без IP-адреса; нужен MAC-адрес и общая сеть второго уровня, на iOS ещё и MAC-адрес устройства |

Для нового MikroTik логин обычно `admin`, пароль пустой или напечатан на наклейке. Если у группы пользователя нет прав на какой-то раздел меню, программа помечает его и пишет, каких прав не хватает.

Если у пользователя истёк пароль (RouterOS просит новый после `/user/expire-password`), программа сразу после входа предложит его задать. «Пропустить» — работать со старым, при следующем входе роутер спросит снова. Вопрос приходит через консоль роутера, поэтому его видно по TCP 8291, SSH и MAC-Telnet, но не по API.

Чтобы перейти на шифрование, сначала подключитесь другим способом. Если с первой попытки вы получили ошибку про TLS (API-SSL включён, а сертификата нет), выберите в списке «Протокол» вариант «API (8728)». Когда соединение откроется, щёлкните по метке «Без шифрования» в главном окне: откроется окно «Подготовить роутер». В нём четыре шага, любой можно отметить или снять, а команды выполнятся по кнопке «Применить»:

- выпустить самоподписанный сертификат и включить API-SSL (8729);
- разрешить API через туннель SSH (`forwarding-enabled=local`);
- добавить группу пользователей `networkhelm` с правами, которые нужны программе; под неё можно завести отдельного пользователя вместо `admin`;
- выключить открытый API (8728) и Telnet; пока это подключение идёт через API 8728, этот шаг недоступен, иначе оно бы оборвалось.

Дальше подключайтесь по API-SSL: отпечаток сертификата программа спросит один раз.

В окне Container RouterOS в меню строки есть Shell и Log. Shell открывает терминал роутера с `/container/shell` в этом контейнере, `exit` возвращает в консоль роутера. Log открывает вкладку Log, последние 100 строк каждого контейнера (RouterOS 7.20 и новее), только со строками этого контейнера, остальные выбираются списком рядом с поиском. До 7.20 роутер пишет вывод контейнера только в свой журнал, с темой `container`, если у контейнера включено журналирование.

### OpenWrt

Выберите платформу OpenWrt. Есть два способа:

- SSH, порт 22. Нужен пароль root или ключ. На только что прошитом роутере пароль задают в LuCI, в разделе System, Administration.
- ubus по HTTP (порт 80) или HTTPS (порт 443). Нужны LuCI с модулем ubus у веб-сервера и rpcd; входят под root с его паролем. Такой вход получает то, что разрешает ACL LuCI. Окна аренд DHCP, ARP и клиентов Wi-Fi отвечают «Permission denied», формы показывают параметры без типов и подсказок LuCI, а разделов, для конфига которых не установлено приложение LuCI, в меню нет. Файл ACL из [пакета для OpenWrt](server/README.ru.md#прямо-на-роутере-openwrt) всё это снимает, вход по SSH — тоже.

Сверху главного окна можно переключать вид меню: «Вид OpenWrt», «Единый вид» (меню, которые у программы есть для любого роутера) и «Вид LuCI».

### OPNsense

На роутере создайте ключ API: System, Access, Users, нужный пользователь, API keys. Скачается файл с ключом и секретом. В программе в поле «Пользователь» впишите ключ, в поле «Пароль» секрет. Порт 443.

### pfSense

Нужен установленный пакет pfSense-pkg-RESTAPI версии 2: без него pfSense не отвечает на API. Войти можно двумя способами: оставить поле «Пользователь» пустым, а в «Пароль» вписать ключ из System, REST API, Keys; либо указать логин и пароль локального пользователя.

### VyOS 1.4 и новее

Нужно включить HTTP API и создать ключ: `set service https api keys id <имя> key <ключ>`, затем `commit` и `save`. В программе ключ вписывается в «Пароль», поля пользователя у VyOS нет. Каждая правка сразу применяется и сохраняется.

### Keenetic и Netcraze

Netcraze — марка, под которой Keenetic продаёт роутеры в России; у обоих одна и та же KeeneticOS, и программа работает с ними одинаково. Программа обращается к роутеру через RCI — HTTP-интерфейс, которым пользуется его собственный веб-интерфейс. Укажите логин и пароль веб-интерфейса либо оставьте логин пустым и укажите паролем токен доступа KeeneticOS 5.2 (раздел «Пользователи и доступ»). Пользователь с тегом `readonly` получает окна только для чтения.

Из домашней сети достаточно адреса роутера и HTTP (порт 80). Из интернета роутер принимает только HTTPS, на HTTP отвечает «403 insufficient security level». Подключайтесь к его облачному имени на порт 443: KeenDNS выдаёт имена в keenetic.link, keenetic.pro, keenetic.name и keenetic.io, CrazeDNS у Netcraze — в netcraze.link, netcraze.pro, netcraze.club, netcraze.io и crazedns.ru. Такое имя в окне подключения сразу выбирает Keenetic по HTTPS, не прощупывая порты облака. Если HTTPS проброшен на другой порт, адресом всё равно должно быть имя, а не IP: без имени в TLS роутер обрывает соединение. Облако отвечает за одно имя с нескольких узлов, и узел может предъявить свой сертификат вместо сертификата роутера: тогда программа снова покажет окно с отпечатком и кнопкой «Доверять», а не оборвёт подключение.

Меню, окна и их поля берут названия из словаря веб-интерфейса самого роутера (`/assets/language/locale.<язык>.json`) на языке программы: с русской программой меню выглядит как в веб-интерфейсе этого роутера — Системный монитор, Интернет, Мои сети и Wi-Fi, Сетевые правила, Управление. Поле, которого веб-интерфейс не показывает, например счётчики ошибок интерфейса, называется по-своему. Роутер без словаря нужного языка получает английские названия.

В Системном мониторе те же карточки, что в вебе. Интернет — подключение с графиком скорости раз в секунду, адресом, маской, шлюзом, MAC-адресом, DNS-серверами, именем KeenDNS, контентным фильтром и трафиком. О системе — загрузка процессора и память, модель, версия KeeneticOS, канал обновления и автообновление, время работы, текущее время, активные соединения, доступ из интернета, режим KeenDNS, сервисный код и серийный номер. Приложения — серверы WireGuard и OpenConnect, включены или нет. Мои сети и Wi-Fi — домашние сети с клиентами в Wi-Fi и по проводу и их точки доступа с диапазоном, каналом и защитой. Сетевые порты — скорость каждого порта и порт провайдера. Монитор Wi-Fi — загруженность канала каждого радиомодуля, ширина канала, клиенты и температура, ретрансляторы Wi-Fi-системы. Монитор трафика — клиенты, которые больше всего передали и приняли за последние три минуты. Всё это один запрос к роутеру, как его делает веб-интерфейс: роутер со слабым процессором не перегружается. Есть ли обновление, монитор не показывает: веб-интерфейс спрашивает об этом сервер обновлений (`components list`), программа — нет.

Меню повторяет веб-интерфейс: те же пять групп, те же пункты в том же порядке и с теми же подписями. Пункт виден, если веб показал бы свою страницу этому роутеру: программа читает установленные компоненты (`show version`) и режим (`show system mode`) и проверяет те же условия, что код веба, — без компонента corewireless нет точек доступа, Wireless ISP, Монитора Wi-Fi и контроля доступа, без mws — Wi-Fi-системы, без компонентов USB-модемов — Mobile, без модемов QMI и LTE — SMS и USSD, без dsl и usbdsl — DSL, без ntce — IntelliQoS, без storage — Накопителей и устройств, без opkg — OPKG, без wireguard, openvpn, ipip, gre и eoip — их вкладок в Других подключениях, без ndns и ddns — доменного имени, в режиме ретранслятора нет страниц интернета и сетевых правил. Статус — Системный монитор, Монитор трафика (десять клиентов, которые больше всего приняли и передали за последние три минуты, с их скоростью) и Монитор Wi-Fi (каждый радиомодуль с каналом, шириной, загруженностью канала и клиентами). Интернет — Кабель Ethernet (подключения по кабелю и PPPoE поверх них), Mobile (USB-модемы), DSL (состояние линии и её настройки), Wireless ISP (подключение к чужой сети Wi-Fi), все с живой скоростью, трафиком и проверкой интернета; Другие подключения — вкладки VPN-подключений (PPTP, L2TP, SSTP и остальные виды), WireGuard и его пиров, OpenVPN, IP-туннелей IPIP, GRE и EoIP и IPv6 через IPv4; Приоритеты подключений; SMS и USSD модема. Мои сети и Wi-Fi — клиенты, точки доступа, сегменты, Wi-Fi-система с ретрансляторами и настройками, IntelliQoS. Сетевые правила — Интернет-фильтры (контентный фильтр, настройка DNS, перехват DNS-запросов, DNS-прокси), межсетевой экран с вкладками IPv4 и IPv6, переадресация портов с правилами UPnP, маршрутизация, доменное имя KeenDNS, контроль доступа Wi-Fi. Управление — система с прошивкой, синхронизацией времени, конфигурацией, индикаторами и кнопками; Накопители и устройства (диски USB с разделами); Приложения — список приложений веба (серверы VPN, SMB, медиатека, UDP-прокси и другие) с отметкой, установлен ли компонент, и вкладки серверов OpenConnect и WireGuard; пользователи и службы, к которым они допущены; Диагностика с Ping, Traceroute и активными соединениями; OPKG. Окна, которых в вебе нет отдельной страницей, стоят в конце своих групп: DHCP-сервер и ARP — в Моих сетях, DNS и NAT — в Сетевых правилах, время, ресурсы и расписания — в Управлении. Внизу меню — Интерфейсы (все интерфейсы роутера с живой скоростью), IPv6, системный журнал (последние 500 строк, дальше только новые) и командная строка.

Все настройки строятся по самому роутеру. Программа спрашивает у его CLI, какие есть команды (`help`, как веб-CLI для своих подсказок), и делает окно из каждого раздела, где хранятся настройки, — ip http, ip ssh, dns-proxy, system clock, ntp и другие, — и из каждого интерфейса со всеми настройками его типа: MTU, MAC, адрес, IPv6, ping check, расписание, ограничение скорости, аутентификация PPPoE. В меню интерфейс назван только по имени — Bridge0, WifiMaster0/AccessPoint1, а окно — полным контекстом, interface Bridge0. Команда с одним значением — текстовое поле, с вариантами — список, с несколькими значениями — поле на каждое, включено-выключено — флажок; справка команды — подсказка поля. У команд, которые что-то делают, а не хранят значение, например перезагрузки или генерации ключей, полей нет. Новая KeeneticOS или другая модель получает свои настройки без новой версии программы. В меню эти окна сгруппированы по первому слову раздела: Интерфейсы, IP, IPv6, DNS, Wi-Fi-система, Настройки системы, VPN и Другие; у раздела, где нечего настраивать, например `cloud` или `eula`, окна нет. Для одной прошивки роутер описывает команды одинаково, поэтому программа хранит описания и словарь на диске по модели, выпуску и компонентам: первое подключение читает их (около 10 секунд через облако), следующие берут с диска.

Кроме того, менять можно имя клиента, его доступ в интернет и постоянный IP-адрес (имя регистрирует клиента, удаление его забывает); SSID, пароль, защиту (без защиты, WPA2-PSK, WPA2-PSK + WPA3-PSK, WPA3-PSK) и включение точки доступа; имя и описание сегментов, подключений и интерфейсов; правила межсетевого экрана — каждое в списке доступа своего интерфейса и направления, как их хранит веб-интерфейс, с переносом перетаскиванием, выключением и описанием; статические маршруты, NAT, пулы DHCP и постоянные аренды, свои DNS-серверы, пользователей со службами, к которым они допущены, имя роутера и домена; новые подключения PPTP, L2TP и SSTP с сервером, пользователем и паролем, описание и включение подключения любого вида (для остальных видов RCI не принимает сервер, их создают в веб-интерфейсе); приоритеты подключений с описанием и многопутевой передачей; список доступа каждой точки доступа — не используется, белый или чёрный список — с MAC-адресами зарегистрированных клиентов (другие роутер отклоняет: «MAC address … is unknown»). Протокол правила межсетевого экрана — TCP, UDP, ICMP, ESP, GRE, IPv4, IPIP, номер другого протокола или служба из списка веба, например «TCP/22 - Secure Shell (SSH)»: служба уходит на роутер протоколом и портом назначения. Тип и код ICMP списки доступа IPv4 у KeeneticOS не хранят. Адреса правила пишутся как 192.0.2.0/24 или одним адресом, пустое поле — любой; порты — 22, 1000-2000, <1024 или >1023. Правило переадресации портов — как в вебе: вход (интерфейс или подсеть), выход (этот роутер, зарегистрированный клиент, другой адрес или интерфейс), протокол из того же списка, что в вебе (TCP, UDP, TCP/UDP, ICMP, все протоколы и 41 служба), одиночный порт с переадресацией на другой или диапазон, расписание; правила переставляются перетаскиванием и выключаются переключателем. Подключения к провайдеру правятся как в вебе: настройка IPv4 (автоматическая, ручная или не используется) и IPv6, DNS-серверы и отказ от DNS провайдера, MAC-адрес, имя устройства, MTU, 802.1x, Ping Check, туннель PPPoE, PPTP или L2TP поверх кабеля с учётной записью и приоритет подключения; у Wireless ISP — сеть, защита и ключ, BSSID, режим «постоянно» или «по требованию», TTL; у модема — APN, тип сети и роуминг. WireGuard создаётся из текста файла .conf (роутер разбирает его сам, как кнопка «Загрузить из файла» в вебе) или из полей с парой ключей, которую делает роутер. Частный ключ роутер не отдаёт: пустое поле его не меняет, новую пару делает отдельная кнопка. Пиры — свой список с адресом и портом, разрешёнными подсетями, keepalive и общим ключом. OpenVPN создаётся из текста файла .ovpn, IP-туннель — с адресом, удалённой стороной и источником, IPv6 через IPv4 — с адресом брокера. Правила IPv6 межсетевого экрана устроены как правила IPv4 и хранят тип и код ICMPv6. Расписание задаётся строкой вида «start 08:00 mon,tue; stop 17:00 mon,tue», `*` — каждый день. Индикаторы — режим (все включены, выключены все, основные или индикаторы портов) с расписанием и задача каждого индикатора; кнопки — действие на нажатие, двойное и долгое нажатие (действие, которое роутер защищает, например сброс долгим нажатием Reset, только показывается). Прошивка — канал и автообновление; «Проверить обновления» спрашивает сервер обновлений, «Обновить KeeneticOS» после подтверждения скачивает версию, пишет её во flash и перезагружает роутер. SMS отправляются, отмечаются прочитанными и удаляются; USSD-запрос ждёт ответа оператора до минуты; накопитель USB извлекается безопасно. DSL, OPKG и IntelliQoS только показываются. Окно сравнения конфигураций работает и с Keenetic: running-config разбирается по разделам CLI. Правка применяется сразу, и в том же запросе программа просит роутер сохранить конфигурацию, как это делает веб-интерфейс.

Пароль пользователя уходит на роутер хэшем MD5 от «пользователь:realm:пароль» и NT-хэшем — теми же двумя хэшами, что отправляет веб-интерфейс; NT-хэш проверяют VPN-серверы с MS-CHAP.

Командная строка отправляет каждую строку в RCI (`parse`), как веб-CLI роутера, и печатает ответ так, как его печатает CLI по SSH: имена полей выровнены по двоеточию, вложенный блок правее. Контекст сохраняется между строками (`interface Bridge0`, затем `description …`, затем `exit`). Долгая команда, например `tools ping 8.8.8.8`, печатает строки по мере ответа роутера, Ctrl+C останавливает её и на роутере. Настоящий CLI по SSH открыт только из домашней сети (`ip ssh` с уровнем доступа private). Если SSH роутера проброшен из интернета, укажите его адрес и порт в поле «SSH» окна подключения, например 192.0.2.1:2222: тогда командная строка идёт по SSH с логином и паролем веб-интерфейса. Telnet программа не использует.

Роутер можно вести и по одному SSH, не открывая веб-интерфейс в интернет: способ «RCI через SSH» в окне подключения. Адрес и порт — от SSH роутера, логин и пароль — от веб-интерфейса. Программа узнаёт по SSH адрес домашней сети роутера (`show interface`) и ходит к RCI через туннель SSH на этот адрес: сам роутер не отвечает веб-интерфейсом на запросы со своего loopback. Окна и командная строка идут по одному соединению SSH.

Проверено на Keenetic Launcher (KN-1221) с KeeneticOS 5.1.8 через CrazeDNS и через SSH, проброшенный на порт 2222: все окна и меню по компонентам роутера; правила межсетевого экрана IPv4 и IPv6, переадресации портов всех видов, расписание и подключение WireGuard с пиром созданы, изменены и удалены, после проверки конфигурация роутера совпадает с исходной. Настройки подключений к провайдеру на нём только прочитаны: через них тестер выходит в интернет. Модема, DSL и USB у этого роутера нет, поэтому SMS, USSD, DSL и накопители на настоящем роутере не проверены; установку прошивки не запускали.

### Linux по SSH

Выберите в списке устройств «Linux / хост по SSH». На Linux-хосте программа читает интерфейсы, адреса, маршруты, соседей, сокеты (`ss`), хранилище, процессы, службы и журнал (journald или logread) и меняет то, что администратор меняет по SSH. Окна называют его хостом, не роутером. Команды, которым нужен root, выполняются как есть, если вход под root; через `sudo -n`, если sudo пускает без пароля; иначе через `sudo -S` с паролем входа. При входе по ключу впишите пароль и в поле пароля: он уходит только в sudo. Каждая команда через sudo — строка в журнале хоста, поэтому окна, которым нужен root, читаются раз в 30 секунд и сразу после правки из программы. Команды окон занимают не больше шести каналов SSH: OpenSSH открывает на одном соединении десять (MaxSessions), остальные остаются терминалу и файлам.

Системный монитор хоста — загрузка процессора с графиком, память и подкачка, средняя нагрузка, дистрибутив, ядро, архитектура, виртуализация, процессор, время работы; сеть — интерфейс маршрута по умолчанию с графиком скорости раз в секунду, адреса интерфейсов, шлюз и DNS; диски с заполнением; службы — упавшие, сколько работает, сколько портов слушается, межсетевой экран, нужна ли перезагрузка; процессы, которые больше всех занимают процессор и память; кто вошёл; температуры, если ядро их отдаёт. Сокеты — все соединения и отдельная вкладка «Listening Ports»: порт, адрес, протокол, процесс с PID и пользователь, как у `lsof -i` или `ss -tulnp`. Память процессов — в КБ, МБ и ГБ.

Интерфейсы — MTU, комментарий и включение; на вкладке «Virtual» создаются и удаляются VLAN (на выбранном интерфейсе, с номером 1–4094), мосты, интерфейсы dummy и туннели к другому хосту: GRE с ключом или без, GRETAP, IPIP, SIT, VXLAN и GENEVE с VNI и портом UDP (4789 и 6081, если не задан другой; без порта ядро поставило бы VXLAN на 8472). Туннель без локального адреса берёт тот, с которым хост уходит к удалённому концу. «Keep After Reboot» сохраняет туннель в netplan, NetworkManager, systemd-networkd или ifupdown, кроме GENEVE: его netplan и NetworkManager не знают. Туннели, которые ядро создаёт само при загрузке модуля (gre0, tunl0, sit0 и подобные), не показываются. Адреса и маршруты правятся на месте, добавляются и удаляются, постоянные соседи добавляются и удаляются; всё через `ip`, то есть в работающей системе. Галка «Keep After Reboot» в форме пишет ту же правку в сетевую конфигурацию дистрибутива, чтобы она пережила перезагрузку: в профиль NetworkManager (`nmcli connection modify`), в свой файл netplan `/etc/netplan/90-networkhelm.yaml` с проверкой `netplan generate`, в дополнение `networkhelm.conf` к файлу `.network` systemd-networkd или строками `post-up`/`pre-down` в блок интерфейса ifupdown с проверкой `ifquery`. Программа ничего не перезапускает: работающая система правку уже получила. Перед записью файл копируется, и если проверка не прошла, копия возвращается. Удаление адреса, маршрута или виртуального интерфейса убирает его и из конфигурации, если он записан там. wicked, старый формат ifupdown с `address` и `netmask` и файлы netplan в одну строку программа не правит; где менеджера нет, галка отвечает, что правка действует до перезагрузки. Интерфейс, через который пришла сессия, программа не выключает и не удаляет, и адрес, на который она пришла, не удаляет.

Хранилище — смонтированные файловые системы с заполнением, монтирование, перемонтирование и отключение; диски и разделы (`lsblk`) с моделью, серийным номером и файловой системой; записи `/etc/fstab`; SMART (`smartctl`) — здоровье, температура, часы работы, перераспределённые и ожидающие секторы, износ, и короткий тест выбранного диска. В контейнере SMART нет: дисков у него нет.

Журнал хоста разбит на вкладки: System — весь журнал, Kernel — сообщения ядра, Authentication — вход и sudo (facility auth и authpriv), Errors — сообщения с уровнем err и выше, Previous Boot — журнал прошлой загрузки, если journald хранит его на диске. Где есть journald, программа читает его (`journalctl`, потом только новые строки после последней прочитанной); без него — буфер `logread`, файлы `/var/log/messages`, `/var/log/syslog`, `/var/log/auth.log`, `/var/log/secure` и `dmesg`. Вход вне групп `adm` и `systemd-journal` на Debian и Ubuntu видит в журнале только свои строки, поэтому такой журнал программа читает через root. Каждое чтение через sudo само становится строкой журнала, поэтому такие вкладки обновляются раз в 30 секунд; вход под root обновляет их на каждом опросе. В контейнере LXC ядро своих сообщений не отдаёт: вкладка Kernel там пустая.

Межсетевой экран показывает, кто управляет правилами хоста, и вкладку на каждый найденный инструмент. ufw — правила с номерами, как их считает `ufw delete`, включён ufw или нет; новое правило — действие, направление, протокол, порты, адреса, интерфейс и комментарий; настройки — включение, политики по умолчанию, журналирование. Без правила для порта сессии ufw не включается: работающую сессию он оставит, а следующий вход отклонит. firewalld — службы, порты, протоколы, источники, интерфейсы и rich rules каждой зоны, добавляются и удаляются сразу в работающей и в постоянной конфигурации; зоны с target и маскарадингом, «Сделать зоной по умолчанию», «Перезагрузить» и «Сохранить работающую конфигурацию как постоянную». nftables — правила с handle и счётчиками, добавляются в цепочку таблицы и удаляются по handle; цепочки с hook, priority и policy. iptables и ip6tables — правила каждой таблицы и цепочки в том порядке, в котором их проверяет ядро, добавляются в конец или на заданное место; цепочки с политиками и счётчиками. «Сохранить для загрузки» записывает правила туда, откуда их берёт служба дистрибутива: /etc/iptables/rules.v4 в Debian и Ubuntu (загружает iptables-persistent), /etc/sysconfig/iptables в Fedora, RHEL и openSUSE, /etc/iptables/rules-save в Alpine, /etc/iptables/iptables.rules в Arch и /etc/nftables.conf, /etc/sysconfig/nftables.conf или /etc/nftables.nft для nftables. Где правила ведёт ufw или firewalld, они записывают их заново при запуске, и программа поверх них не сохраняет.

Перед каждой правкой межсетевого экрана хост сохраняет текущие правила (iptables-save, nft list ruleset, копия /etc/ufw или /etc/firewalld) и запускает задачу, которая вернёт их через 60 секунд. После правки программа выполняет команду по тому же соединению; если хост ответил за 10 секунд, задача снимается. Правка, которая оборвала сессию, сама откатится в течение минуты. Правило, которое оставляет работающую сессию и отклоняет новые входы, ловит второй вход: перед первой правкой экрана программа один раз входит на хост заново с теми же адресом и учётными данными и, если вход прошёл, повторяет его после каждой правки. Не пустил — прежние правила возвращаются сразу, а окно говорит, почему правка не осталась. Хост, который не даёт пользователю второй сеанс, проверяется только по своей сессии. Каждый такой вход — строка в журнале входов хоста.

Правила ufw, nftables и iptables правятся на месте и переставляются перетаскиванием строк, правила firewalld правятся на месте. Если правка межсетевого экрана не удалась, сохранённые перед ней правила возвращаются сразу, не дожидаясь минуты.

Пакеты — через менеджер, какой есть на хосте (apt, dnf, yum, zypper, pacman, apk): «Установленные», где «Новый» ставит пакет по имени, а «Удалить» удаляет; «Обновления» с обновлением выбранных, обновлением всех и обновлением списков. Каждая команда отвечает тем, что напечатал менеджер. Службы systemd и OpenRC: запуск, остановка, перезапуск, перечитывание, включение и выключение автозапуска, автозапуск виден в колонке. Процессы: Hang Up, Terminate и Kill.

В терминале такого хоста есть кнопка, которая делает консоль root: она набирает `sudo -s` и сама отвечает sudo паролем входа, когда тот его спрашивает.

Проверено в контейнерах LXC с Debian 12 (ifupdown), Ubuntu 24.04, Fedora 44, Arch Linux и openSUSE Leap 16 (systemd-networkd), Rocky Linux 9 (NetworkManager) и Alpine 3.24 (ifupdown-ng, OpenRC и busybox): на каждом созданы интерфейс dummy и адрес с сохранением в конфигурацию и удалены, после этого конфигурация совпала с исходной. SMART проверен на узле Proxmox с двумя дисками SATA.

### VPN на Linux-хосте

В группе VPN меню — окно на каждый VPN, найденный на хосте: WireGuard, AmneziaWG, OpenVPN, IPsec (strongSwan через swanctl), Libreswan, L2TP (xl2tpd), PPTP (pptpd), OpenConnect (ocserv), OpenConnect Client, PPTP Connections и SSTP Client для хоста-клиента, Tailscale и ZeroTier; поставленный кнопкой Install Now появляется сразу. В Users — пользователи всех серверов сразу, в Connections — живые сессии. Overview есть на любом хосте: каждый из них, установлен ли он и какие пакеты ему нужны; Install Now после подтверждения ставит отмеченные строки менеджером пакетов хоста и показывает его вывод, а пакет, которого нет в репозиториях хоста, называет вместе с тем, откуда он берётся (репозитории Tailscale и ZeroTier). AmneziaWG, которого нет в пакетах дистрибутивов лаборатории, Install Now ставит сам: инструменты на Ubuntu — из PPA Amnezia, на остальных — сборкой из исходников последнего выпуска; где модуль ядра не загружается (в контейнере всегда), туннель ведёт amneziawg-go через /dev/net/tun, собранный Go с go.dev; архив Go сверяется с суммой go.dev и удаляется после сборки. Подъём туннеля или клиента хоста, NAT через ufw или firewalld и порты, которые сервер открывает в firewalld, перезапуск WireGuard, OpenVPN или AmneziaWG после правки и настройки Tailscale и ZeroTier, меняющие маршруты, идут через тот же сторож, что и правка межсетевого экрана. NAT для клиентов сервера требует ufw или firewalld; без них его берёт интерфейс wg-quick своими хуками и сервер OpenVPN отдельным юнитом systemd, привязанным к юниту сервера. Новый интерфейс WireGuard и новый сервер OpenVPN сразу запускаются; WireGuard берёт первый свободный порт от 51820, а порт сервера открыт в ufw или firewalld независимо от NAT. DNS интерфейса wg-quick — это DNS самого хоста, ему нужен `resolvconf`; DNS для клиентов задаётся в Client DNS их пиров. Интерфейс с `SaveConfig = true` не правится: wg-quick при остановке записал бы поверх правки работающий интерфейс. В окне WireGuard есть New Server и Import Client Config. New Server открывает форму, вкладки которой хост заполняет сам: следующее свободное имя wgN, первый свободный порт от 51820, первая сеть 10.N.0.0/24, не пересекающаяся с адресами и маршрутами хоста, адрес интерфейса маршрута по умолчанию для клиентов (у частного адреса — подсказка, что клиентам из интернета нужен внешний), DNS для клиентов, NAT, автозапуск и первый клиент; «Создать и запустить» пишет файл, проверяет его wg-quick, поднимает интерфейс и показывает конфиг первого клиента с QR-кодом. Адрес, DNS и маршруты для клиентов задаются один раз на интерфейс во вкладке Clients. Import Client Config берёт такой конфиг вставкой или из файла и поднимает его как интерфейс wg-quick; конфигу с DNS нужен resolvconf на хосте. У окна OpenVPN та же пара: New Server на вкладке Servers делает PKI, сервер и первого клиента и показывает его .ovpn с QR-кодом, Import Client Config на вкладке Connections берёт такой .ovpn. Если туннель забирает маршрут хоста по умолчанию, импорт оставляет путь к компьютеру этой сессии мимо туннеля отдельным маршрутом, а новый сервер или подключение включаются в автозапуск только после подъёма под сторожем. Ключи, пароли и общие ключи уходят на хост входом команды, никогда в её командной строке; в чтении и в текстах ошибок они показаны как `(hidden)`. Конфигурации и профили для клиентов открываются текстом для копирования, с QR-кодом, если текст в него помещается.

WireGuard: интерфейсы, которые держат wg-quick, NetworkManager и systemd-networkd, с их пирами, и те, что только работают; новый интерфейс — файл wg-quick. Новый пир получает пару ключей, созданную на хосте, общий ключ и следующий свободный адрес IPv4 из сети интерфейса. Закрытый ключ клиента остаётся на хосте в `/etc/wireguard/networkhelm/<интерфейс>/<имя>.key` с правами 600, поэтому «Client Config» показывает конфигурацию и её QR-код и позже; со снятой галкой «Keep Client Key on Host» ключ удаляется после первого показа конфигурации. «NAT for Clients» маскирует сеть интерфейса и открывает его порт через ufw или firewalld — кто из них держит правила хоста, — а где нет ни того, ни другого, через PostUp и PostDown wg-quick.

OpenVPN: новый сервер получает PKI easy-rsa в `/etc/openvpn/server/<имя>/` (ключи EC P-256, сертификаты на десять лет, CA без пароля), tls-crypt, CRL и сокет управления, через который панель завершает сессии. Клиенты — сертификаты: постоянный адрес и выключение клиента пишутся в его файл настроек клиента, удаление отзывает сертификат и заново выпускает CRL, «Client Config» показывает `.ovpn` с CA, сертификатом, ключом и tls-crypt внутри. Запуск и перезапуск после правки считаются неудачными, если служба через 5 секунд не активна, и тогда возвращается прежний файл. Вкладка Connections — хост как клиент: `.ovpn`, уже лежащий на хосте, копируется к себе, логин уходит в отдельный файл.

IPsec показывает соединения из файлов `/etc/swanctl` и создаёт серверы IKEv2 для клиентов, встроенных в Windows, macOS, iOS и Android: свой CA, сертификат сервера на имя или адрес, по которому к нему приходят клиенты, пользователи с EAP-MSCHAPv2, чьи секреты хранит один файл. Форма и мастер сервера задают предложения IKE и ESP, DPD, время смены ключей, MOBIKE, фрагментацию IKE, уникальность ID, принудительную инкапсуляцию в UDP и когда отправлять сертификат; профиль для Windows или Apple начинается с предупреждения, если в предложениях нет AES256 с SHA256 и группой 14, которые эти клиенты просят. Соединения, созданные не здесь, показываются и остаются как есть. «Start at Boot» — автозапуск службы strongSwan, он один для всех соединений. Users показывает для каждого пользователя профиль Apple (`.mobileconfig` с CA), профиль Android для приложения strongSwan (`.sswan`) и скрипт PowerShell для Windows. NAT для пула идёт по политике IPsec, UDP 500 и 4500 открываются. Вкладка Clients — хост подключается к чужому серверу по EAP или общему ключу, с CA сервера и сетями, которые идут через туннель. Libreswan показывает conn из `/etc/ipsec.conf` и `/etc/ipsec.d`, создаёт и правит только свои — по одной в файле `/etc/ipsec.d`, общий ключ в отдельном файле секретов; pluto выходит с 0 и для conn, которую принять не может, поэтому новый файл остаётся, только если `ipsec addconn` не сообщил об ошибке.

L2TP — сервер для клиентов, встроенных в Windows, macOS и iOS: xl2tpd со своим файлом pppd и соединение strongSwan в транспортном режиме с общим ключом, который создаёт хост, если ключ не задан. Пользователи — строки `/etc/ppp/chap-secrets` под именем этого сервера; строки других серверов остаются как были. UDP 1701 открыт только для пришедшего через IPsec: в ufw — правилом с политикой IPsec, в firewalld — прямым правилом, которое отбрасывает его открытым текстом. Stop заодно завершает SA IPsec этого сервера. PPTP отдаёт логины и трафик пользователей любому, кто их записал: MS-CHAPv2 и MPPE вскрываются, поэтому мастер создаёт сервер только с отмеченным «Insecure, Create It», а правка сервера требует «Insecure, Change It». Мастер задаёт адреса, DNS, NAT и первого пользователя и отвечает скриптом для Windows; форма сервера задаёт ещё предел подключений, MTU, MRU и эхо LCP. «PPTP Connections» подключает хост к такому серверу по ответу его мастера, и ему нужен только клиент pptp: pptpd на клиенте нет.

OpenConnect — это ocserv: настройки, сертификат на имя, по которому приходят клиенты (они закрепляют его pin), и пользователи файла ocpasswd. Изменённый файл проходит `ocserv --test-config` и при ошибке возвращается; работающий сервер получает его через `occtl reload`, а при смене портов или сети перезапускается. OpenConnect Client и SSTP Client создают на каждое подключение юнит systemd: openconnect читает пароль из файла с правами 600, sstpc оставляет его pppd, который находит пароль в chap-secrets. Подключение SSTP проверяет сертификат сервера по его файлу CA или по набору CA системы, если не отмечено Skip Certificate Check; оно может пускать весь трафик хоста в туннель (путь к текущей сессии остаётся мимо него), брать DNS сервера и задавать MTU. Connect ждёт устройство туннеля до 20 секунд, и если юнит по дороге остановился, показывает конец его журнала. У AmneziaWG окно WireGuard для awg-quick в /etc/amnezia/amneziawg: пиры, конфиги клиентов с QR-кодом, New Server и Import Client Config и вкладка Disguise — Jc, Jmin, Jmax, S1, S2 и H1–H4, а S3, S4 и I1–I5 там, где их называет awg хоста (версии 1.5 и 2.0). New Server предлагает маскировку, которую AmneziaVPN даёт новому серверу, в форме версии 1.0, понятной любому клиенту: 4–6 мусорных пакетов по 10–50 байт, дополнение 15–149 байт, S2 не равно S1 + 56, четыре своих типа сообщений. Диапазоны проверяются: Jc 1–128, Jmin не больше Jmax, Jmax до 1280, S1 до 1132, S2 до 1188, S3 до 1216, S4 до 32, H1–H4 от 5 до 2147483647 без пересечений. Конфиг клиента несёт маскировку своего интерфейса; AmneziaVPN и приложения AmneziaWG берут его файлом или QR-кодом. Правка маскировки перезапускает работающий интерфейс под сторожем. На хосте с OpenRC, например Alpine, «Start at Boot» сначала ставит /etc/init.d/awg-quick — такую службу не даёт ни один пакет. Tailscale показывает узел, его настройки и узлы его сети. Узел входит только по ключу авторизации, введённому в форме, — на сервер Tailscale или на указанный в Login Server, например Headscale; иначе Connect отвечает ссылкой входа, которую открывает сам пользователь, а Log Out завершает вход. «Use as Exit Node» пускает трафик хоста через выбранный узел. Кроме маршрутов, DNS, SSH и выходного узла форма задаёт автообновление, веб-интерфейс и пользователя-оператора, а вкладка Firewall — SNAT для маршрутов подсетей, stateful-фильтрацию и режим netfilter; каждая правка идёт через tailscale set под сторожем. ZeroTier вступает в сети по их ID, выходит из них и задаёт, что сеть может менять на хосте: управляемые и глобальные адреса, маршрут по умолчанию и DNS. Сеть показывает свои маршруты и DNS-серверы, вкладка Peers — корневые серверы и узлы с задержкой и путём, вкладка Node задаёт в local.conf порт, проброс портов и TCP-ретранслятор, после чего служба перезапускается под сторожем.

Users — один список по всем серверам, как Secrets у PPP в RouterOS: пир WireGuard по имени в комментарии, сертификат OpenVPN по common name, секрет EAP, пользователь ocpasswd и строка chap-secrets у L2TP или PPTP — один пользователь, где имена совпадают. Новый пользователь получает то, что нужно каждому выбранному серверу, и один пароль для всех служб, которые его берут; если пароль не введён, хост придумывает его только для IKEv2: секрет EAP хранит пароль, и его можно показать ещё раз. Выключение пользователя, снятие с него сервера и удаление действуют на всех серверах, где он есть; сессия L2TP или PPTP при этом длится, пока клиент не уйдёт сам. «Client Configs» показывает конфигурацию для каждого из его серверов. «Rate Limit» записывается как в RouterOS, `5M/20M` — отдача и загрузка клиента, и ограничивает адреса, которые у пользователя свои в WireGuard: HTB на интерфейсе в сторону клиента и на IFB для того, что приходит от него. Ограничения хранятся в `/etc/networkhelm/vpn-limits` и ставятся заново правилом udev, когда интерфейс появляется снова.

Connections показывает плитку на каждую службу с портом, числом сессий и скоростью, график скоростей и живые сессии, которые читаются каждые 3 секунды: пиры WireGuard и AmneziaWG с рукопожатием моложе трёх минут, клиенты OpenVPN из файла состояния, IKE SA strongSwan, пользователи ocserv с программой-клиентом, которую они сообщают, и сессии accel-ppp. Байты пира WireGuard и AmneziaWG считаются с подъёма интерфейса, а не с начала сессии. Disconnect выключает пира WireGuard или AmneziaWG, чтобы его клиент не вернулся сразу, остальные сессии обрывает; «Open Peer» и «Client Config» работают с сессиями обоих. Журнал подключений берёт OpenVPN и charon из журнала systemd. WireGuard и AmneziaWG историю не ведут, поэтому «Install Collector» ставит на хост скрипт, который таймер systemd, а под OpenRC cron, запускает каждые 30 секунд; он пишет начало, конец и счётчики сессий WireGuard, OpenVPN и strongSwan в `/var/lib/networkhelm/vpn-sessions.jsonl`. Журнал показывает сутки, неделю или месяц, суммы по пользователям и выгружается в CSV.

Проверено в контейнерах LXC с Debian 12, Ubuntu 24.04, Fedora 44, Alpine 3.24 и Arch Linux: пиры WireGuard, NAT и сессии в панели, ограничение скорости — с `2M/5M` 4,78 Мбит/с к клиенту и 1,93 от клиента при 1,4 Гбит/с без ограничения; IKEv2 strongSwan с Libreswan 5.4.1; GRE и VXLAN между Debian (ifupdown) и Ubuntu (systemd-networkd); Tailscale 1.98 и ZeroTier 1.16 без аккаунтов. Каждый сервер ещё и создан только окнами программы на Debian 12, а Ubuntu 24.04 подключилась к нему через Import Client Config: через WireGuard с раздельным и полным туннелем, OpenVPN, ocserv с OpenConnect и AmneziaWG (в контейнере модуль не грузится, туннель идёт через amneziawg-go) прошли ping и HTTP, у IKEv2 SA установлена и ping идёт по виртуальному адресу. L2TP дошёл до SA IPsec и управляющего соединения: pppd в этих контейнерах не открывает `/dev/ppp`, поэтому сессии L2TP, PPTP и SSTP не запускались, как и accel-ppp, которого нет в пакетах дистрибутивов.

Если хост — узел Proxmox VE (на нём есть `pvesh`), в меню появляется пункт Proxmox — одно окно с вкладками. Node: версия, ядро, режим загрузки, время работы, процессоры, загрузка ЦП, IO delay, load average, память, своп, KSM и корневой диск. Storage: хранилища узла с занятым и свободным местом. Virtual Machines и LXC Containers: гости всего кластера с узлом, ЦП, памятью, диском и временем работы; Start, Shutdown, Stop, Reboot, Suspend и Resume, форма гостя меняет ядра, сокеты у ВМ, память, своп у контейнера, автозапуск и описание; Console открывает терминал программы с `qm terminal` (ВМ нужен порт `serial0: socket`, выход — Ctrl+O) или `pct enter`, только у гостей этого узла. Snapshots: новый снимок с именем, описанием и у ВМ с памятью, Roll Back и удаление. Backups: копии в активных хранилищах узла; новая — `vzdump` в выбранное хранилище с режимом, сжатием и заметкой, удаление — `pvesm free`. Tasks: последние 50 задач узла с журналом и остановкой работающей. Cluster Log: журнал кластера. Всё идёт через `pvesh` от root или через sudo, без токенов API; таблицы читаются раз в 30 секунд и сразу после команды программы. Команда, которая запускает задачу, ждёт её конца до 20 секунд и при неудаче показывает конец журнала задачи; `vzdump` не ждёт, за ним следит Tasks. Сети узла показывает окно сетей хоста. Восстановления из копии и миграции между узлами нет.

### Прокси на Linux-хосте

Overview показывает Squid, tinyproxy, 3proxy, Dante, shadowsocks-libev, sing-box и Xray — установлен ли, состояние службы, порты, которые слушает процесс, и файл настроек; Install Now после подтверждения ставит выбранные строки и показывает вывод установки: пакеты — одним вызовом менеджера хоста, а Xray и sing-box там, где их нет в репозиториях, — из последнего выпуска на GitHub, и колонка Packages тогда показывает страницу выпусков. Выпуск ставит программу в /usr/local/bin, у Xray ещё geoip.dat и geosite.dat с проверкой архива по его .dgst, службу systemd или OpenRC и пустой конфиг, если его не было; curl и unzip, если их нет, ставит менеджер. Squid — порты, кэш, DNS, тайм-ауты и журнал из squid.conf (размеры и времена с единицами — 256 MB, 30 seconds: голое число Squid читает в байтах или секундах), вышестоящий прокси, через который идут все запросы (cache_peer с never_direct), кэширование вкл/выкл (cache deny all), правила http_access по порядку (новое правило встаёт перед `http_access deny all`, перетаскивание оставляет правила по свои стороны от `include`), строки acl и пользователи basic_ncsa_auth, чьи пароли хэшируются на хосте (`openssl passwd -apr1`, без openssl — `cryptpw` из busybox). Изменённый squid.conf проходит `squid -k parse` и при ошибке возвращается; работающий Squid получает его через `squid -k reconfigure`, а новый cache_dir его перезапускает. Basic Auth of Users добавляет правило, пускающее пользователей, перед `deny all`; пакеты Debian, Fedora и Alpine разрешают `localhost` выше него, так что с самого хоста Squid по-прежнему пускает без логина. tinyproxy — порт, адреса приёма и исходящих соединений, разрешённые и запрещённые клиенты, порты для CONNECT, ограничения, заголовки Via и X-Tinyproxy, вышестоящий прокси и пользователи BasicAuth — их имена и пароли состоят только из латинских букв, цифр, точек, дефисов и подчёркиваний, иначе tinyproxy их не разберёт; проверки файла у tinyproxy нет, поэтому работающий перезапускается, и если он не поднялся за 3 секунды, возвращается прежний файл. Ещё Squid суммирует свой журнал доступа за 30 дней, с повёрнутыми и сжатыми файлами, по клиентам и по сайтам: запросы и байты за сутки, неделю и месяц. shadowsocks-libev — сервер из config.json (адреса, порт, пароль, шифр AEAD, режим, тайм-аут, плагин, TCP Fast Open, повторное использование порта, no delay, IPv6 первым и DNS-серверы ss-server), перезапуск с возвратом прежнего файла, если служба не поднялась, и Client Link — ссылка ss:// по SIP002 с QR-кодом; серверу на loopback или на всех адресах в ссылку идёт адрес, по которому сессия пришла на хост. Пакет Debian запускает сервер с DynamicUser, и config.json должен читаться всеми, так что пароль из него видит любой пользователь хоста. Dante (danted в Debian и Ubuntu, sockd в Fedora, Arch и Alpine) — настройки вне правил (internal, external и ротация его адресов, методы SOCKS и клиента, пользователи, от которых он работает, тайм-ауты согласования, соединения и простоя, журнал), правила client и socks в том порядке, в котором их проверяет Dante (новое правило встаёт перед правилом своего вида для любых адресов), и пользователи метода username — учётные записи системы без оболочки, пароли которых уходят в chpasswd. Изменённый файл проходит `danted -V` или `sockd -V` и при ошибке возвращается; файл из пакетов не задаёт internal и не проходит проверку, пока адрес не задан. Метод username сверяет пароль с /etc/shadow, который читает только root, поэтому с ним программа ставит `user.privileged: root` (в Debian там proxy, и с ним вход не проходит); новое правило пишет в журнал `error connect disconnect`: без `log:` Dante о клиентах правила ничего не пишет. 3proxy (пакет Fedora) — настройки до правил (DNS и размер его кэша, журнал и число его ротаций, соединения, тайм-ауты, адреса), строки auth, allow, deny и flush вместе со службами, к которым они относятся, в порядке файла и с перетаскиванием, потому что 3proxy читает их по порядку, и пользователи строк users, новый пароль — crypt MD5 (CR); проверки файла у 3proxy нет, поэтому работающий перезапускается, а если не поднялся, возвращается прежний файл. sing-box и Xray — входы (тег, вид, адрес, порт, TLS или Reality, транспорт, пользователи) и пользователи в таблицах, новый пользователь с UUID или паролем, которые выдаёт хост, Client Link для VLESS, VMess, Trojan, Shadowsocks и Hysteria2 с QR-кодом (открытый ключ Reality программа выводит из закрытого сама) и config.json целиком в редакторе Edit config.json: `sing-box check -c` или `xray run -test -c` читает новый файл на его месте, и при ошибке проверки или если служба не поднялась файл возвращается. New на вкладке Inbounds (или New Server на вкладке Service) — мастер сервера одной из схем: VLESS + REALITY, Shadowsocks 2022, Trojan + TLS, VLESS + WS + TLS и у sing-box Hysteria2 с обфускацией salamander; сертификат — подписанный самой программой, файлы хоста или ACME у sing-box (ссылки сервера с самоподписанным сертификатом позволяют клиенту sing-box его не проверять, а клиенту Xray закрепить, pcs); тег, порт (443, затем 8443, затем свободный выше 20000), сайт, у которого Reality берёт рукопожатие (dl.google.com), и имя первого пользователя уже заполнены, UUID выдаёт ядро, ключ Reality — сама программа, short ID — /dev/urandom; файл проходит проверку, служба запускается и включается в автозапуск, а если не поднялась, возвращается прежний файл и служба останавливается. Вход shadowsocks из примера пакета sing-box, чей пароль лежит в репозитории sing-box, мастер удаляет. Client Links у входа даёт ссылки всех его пользователей с QR-кодом, Remove удаляет вход. Форма входа правит все его настройки: тег, порт и адрес, транспорт (network, путь, Host, имя службы gRPC), TLS или Reality (имена сервера, ALPN, файлы сертификата, цель, short ID и закрытый ключ Reality), sniffing у Xray, шифр и ключ Shadowsocks, у sing-box — salamander и скорости Hysteria2. Секрет, оставленный пустым после «+», хост делает заново; вход, переведённый на Reality, получает ключ, short ID и сайт мастера, на TLS без сертификата — сертификат, подписанный самой программой, а новый тег или порт переносит правило ufw или firewalld. Пользователя можно переименовать, сменить ему flow и секрет. Вкладка Outbounds показывает выходы с их сервером, выходом, через который они идут, и тем, какой из них по умолчанию; New делает direct, block (у Xray) или выход на сервер по ссылке, который может идти через другой выход — цепочка, а Make Default ставит выход первым (и убирает route.final у sing-box). Выход, который ещё называют правило, цепочка или умолчание, не удаляется. Вкладка Routing держит правила по порядку, с перетаскиванием: домены (с поддоменами или full:, keyword:, regexp:), geosite, geoip, адреса и входы уходят в выход или в block — выход blackhole у Xray и действие reject у sing-box. geosite и geoip — файлы Xray, а у sing-box, где своих geosite нет с 1.12, — наборы правил SagerNet, которые sing-box скачивает при запуске. Block Ads добавляет правило, блокирующее category-ads-all. Условия, которых в форме нет, например порты, остаются в правиле и видны в Other Conditions. Ссылки появляются сразу после OK мастера. Порт нового сервера мастер открывает в ufw или firewalld, если один из них ведёт правила, а Remove входа его закрывает. Вход shadowsocks из примера пакета sing-box, чей пароль опубликован в репозитории sing-box, Install Now убирает сразу после установки; пока он в файле, служба sing-box не запускается, не ставится в автозапуск и файл не сохраняется. Вкладка Clients у Xray и sing-box делает клиента на этом хосте по ссылке сервера (vless://, vmess://, trojan://, ss://, hy2://; у Xray — без Hysteria 2): отдельный файл /etc/networkhelm/<программа>/<имя>.json и отдельная служба <программа>-client-<имя>, так что сервер той же программы на хосте свой конфиг сохраняет. Клиент принимает SOCKS на 127.0.0.1 (sing-box на том же порту и HTTP), файл проходит проверку программы, служба запускается и включается в автозапуск. Клиент sing-box до 1.14.4 к серверам REALITY на Xray 26 не подключается (он не шлёт X25519MLKEM768), поэтому для ссылки REALITY сервера Xray вкладка Clients у sing-box на этих версиях отказывает и предлагает клиента Xray. Файл с комментариями, которые допускает Xray, для таблиц не JSON и правится только в редакторе. Xray 26 из выпуска проверен на Debian 12 и Ubuntu 24.04: через серверы VLESS + REALITY и Trojan + TLS, созданные мастером, прошли запросы клиентов Xray, созданных по их ссылкам. System Proxy пишет один адрес с логином в `/etc/environment` (его читают и pacman, и apk), в свой файл apt, в `dnf.conf`, в `/etc/sysconfig/proxy` zypper и в дополнение юнита Docker, после чего Docker перезапускается. Пароли лежат в этих файлах так, как их ждут программы; окна их назад не показывают, а пустое поле пароля оставляет прежний.

### Контейнеры на Linux-хосте

Если на хосте есть `docker` или `podman`, в меню появляется группа Containers — одно окно с вкладкой на каждый её пункт. Окна того, что поставили на хост Install Now или окно пакетов, появляются в меню сразу, а убранного — пропадают, без нового подключения. Программа говорит с API движка через `docker system dial-stdio` (`podman system dial-stdio`) в канале сессии SSH, как `docker -H ssh://`: на хост ничего не ставится, порты не открываются. К движку программа идёт от имени входа, если входу он доступен: root, участник группы `docker` (эта группа на хосте равна root), rootless Docker через `DOCKER_HOST` или сокет в `$XDG_RUNTIME_DIR`. Если движок ответил «permission denied», программа идёт через sudo, как и остальные окна хоста. Вход не под root попадает в системный Podman через sudo, если есть `/run/podman/podman.sock`, иначе — в свой Podman; если сокет входа не отвечает, программа запускает `podman system service --time=900`, и служба сама завершается через 15 минут без соединений. Команда `docker` из пакета podman-docker считается Podman. У Podman 3 (Ubuntu 22.04) нет `dial-stdio`, такой Podman программа не достаёт. В группе всегда есть Overview: Docker, Podman и Compose с версиями и пакетами под теми именами, которые даёт дистрибутив (docker.io в Debian и Ubuntu, moby-engine в Fedora, docker-ce и docker-compose-plugin из репозитория Docker в RHEL и родственных, docker-cli-compose в Alpine, podman-compose там, где стоит только Podman). Где `docker` — сценарий podman-docker, строка Docker так и называется и пакета не предлагает: moby-engine конфликтует с podman-docker. Install Now после подтверждения ставит отмеченные строки менеджером пакетов хоста и показывает его вывод; Docker, которого не было, сразу запускается и включается в автозапуск (`systemctl enable --now docker`, на Alpine — `rc-update` и `rc-service`). Если стоит только Compose v1 (`docker-compose` 1.29.2 в Ubuntu и Debian 12), строка Compose предлагает v2, а v1 стоит отдельной строкой без пакета. На хосте без движка в группе есть только Overview. Пункты группы открывают одно окно Containers с вкладками в порядке меню (Overview, Containers, Images, Volumes, Networks, Stacks, Pods у Podman, Registries, Monitor, System); на хосте без движка в нём только Overview, а вкладки движка появляются в течение пяти секунд после того, как установленный движок начал отвечать. Вход в группе `docker` через Docker получает root на хосте; при первом подключении, на котором это видно, программа говорит об этом строкой над окнами, один раз для каждого хоста.

Containers — строка начинается с букв состояния, как флаги RouterOS: R запущен, P на паузе, S перезапускается, X остановлен, E остановлен с кодом ошибки или мёртв, H здоров, U нездоров; затем имя, стек (проект Compose), образ, статус, время создания, адрес, опубликованные порты, ЦП и память, остальное добавляет меню колонок; Start, Stop, Restart, Pause, Resume, Kill, Hang Up, Recreate with Pulled Image, Duplicate, Save as Image и Remove with Volumes. Форма контейнера разбита на вкладки `docker run`: General, Env, Ports, Mounts, Network, Resources, Restart, Healthcheck, Security, Logging и Runtime, значения пишутся как в командной строке (`8080:80/tcp`, `src:dst:ro`, `512m`, `1m30s`). ЦП, память, pids и политика перезапуска меняются на ходу (`docker update`), новое имя — переименование; любая другая правка пересоздаёт контейнер, и только с отмеченным полем Recreate. Старый контейнер переименовывается, новый создаётся и запускается, и только после этого старый удаляется; если шаг не удался, новый удаляется, а старый получает своё имя и запускается снова. Переменные, в имени которых есть pass, secret, token, key, credential, private или auth, стоят в поле Secret Variables: их значения назад не читаются, пустое значение оставляет прежнее, во вкладке «Описание» они замаскированы. При включённом «Скрывать пароли и ключи» каждая строка поля — точки с глазом, как у пароля, и в журнале правок вместо значений тоже точки. Окно контейнера: «Журнал» (идёт за контейнером; фильтр по тексту, последние 100, 500, 5000 строк или все, время, «Сохранить» пишет показанные строки в файл; stderr — другим цветом), «Терминал» (`exec` с оболочкой и пользователем или `attach`), «Нагрузка» (ЦП в процентах одного ядра, память относительно лимита, сеть и диск в секунду за последние две минуты), «Процессы» (`top`), «Описание» (inspect), «Изменения» (`diff`) и «Файлы» (список читает `ls -la` внутри контейнера, у образа без ls, например distroless или scratch, он пуст; скачивание и загрузка — через архивы API).

Terminal в меню строки сразу открывает оболочку контейнера: bash, если он есть в образе, иначе sh. Вкладка Terminal окна, открытого другим пунктом, сначала спрашивает оболочку и пользователя, пустая оболочка значит тот же выбор.

Images — строка на каждый тег с ID, размером, временем создания и числом контейнеров, которые его используют; Pull с ходом каждого слоя, Pull Again, Tag and Push, History, Inspect, удаление и Remove Forced, Save to File и Load from File (файл остаётся на хосте, на компьютер его переносит окно файлов). Volumes — драйвер, точка монтирования, число контейнеров, которые его монтируют, анонимный ли том; новый том создаётся с драйвером, опциями и метками. Browse показывает файлы тома через служебный контейнер: `alpine:latest` с томом в `/volume`, без сети; он создаётся только после согласия и удаляется, когда окно закрывается, самое позднее через час. Networks — bridge, macvlan и ipvlan с подсетью, шлюзом, диапазоном, IPv6, родительским интерфейсом и режимом, internal и attachable; контейнеры сети, подключение контейнера с алиасом и адресом, отключение. Алиасы на bridge по умолчанию Docker не принимает, и окно говорит это до запроса. Prune контейнеров, образов, томов и сетей сначала показывает, что пропадёт, и удаляет отмеченное по одному, так что элемент, который движок не отдаёт, не мешает остальным.

Stacks — проекты Compose, найденные по меткам их контейнеров, и папки `~/stacks/<имя>` с файлом Compose. Программа зовёт `docker compose` или `podman compose`, иначе `docker-compose` или `podman-compose`, в папке стека и тем же путём, что и движок (через sudo — от root): Up, Down, Down with Volumes, Restart, Pull, Build, службы с состоянием, общий журнал всех контейнеров стека и правка compose.yaml и .env, при которой Compose сначала читает стек с черновиком (`config`), а потом файл заменяется. Новый стек ложится в `~/stacks/<имя>`: файлы из окна, шаблон или клон репозитория Git; Compose читает его до запуска, и стек, который он не прочёл, не остаётся. С программой идут десять шаблонов: nginx, PostgreSQL, Redis, Home Assistant, AdGuard Home, Uptime Kuma, WordPress с MariaDB, Gitea, Grafana и Prometheus, пароли в их .env — заглушки; свой шаблон добавляет «Сохранить как шаблон» в правке стека. Registries хранит логины реестров там же, где программа хранит пароли (раздел «Где лежат данные»). Логин уходит в заголовке `X-Registry-Auth` с каждым pull и push своего реестра из окон Pull и Tag and Push, с pull у Recreate with Pulled Image и с тем, который нужен новому контейнеру или пересозданию из формы, когда образа на хосте нет; на хосте он не остаётся. Образы стека Compose скачивает только со входами самого хоста; `docker login` на хосте выполняется только по кнопке «Войти на хосте», пароль идёт ему на stdin.

Monitor — вкладки «Движок» (версия движка и API, система, ядро, драйвер хранения, cgroup, процессоры и память, контейнеры по состояниям, образы, корневая папка, rootless ли движок и состояние Swarm, который программа только показывает; ниже — контейнеры, которые больше всех занимают ЦП и память), «События» (что движок сохранил за последний час или сутки, затем то, что происходит, с фильтром по виду и по имени, образу или ID), «Диск» (`system df`: сколько занимают образы, контейнеры, тома и кэш сборки и сколько из этого освободила бы очистка); System — daemon.json и «Очистка» контейнеров, образов, томов и сетей; кэш сборки она не трогает. Поды Podman — статус, контейнеры, сколько из них работает, сети; Start, Stop, Restart, Pause, Resume, Kill и удаление вместе с контейнерами.

Сеть macvlan или ipvlan, родитель которой — интерфейс, через который пришла сессия (или VLAN на нём), подключение контейнера к такой сети из окна сети и сохранение daemon.json идут через тот же сторож, что и правка межсетевого экрана: хост вернёт прежнее через 60 секунд, если программа не достучится до него после правки, а второй вход проверяет, что новые сеансы по-прежнему пускают. daemon.json сначала проверяется `dockerd --validate --config-file`; потом он записывается, Docker перезапускается (`systemctl restart docker`, на Alpine `rc-service docker restart`), и программа ждёт `docker info` до 30 секунд. Если шаг не удался или сессия потеряна, прежний файл возвращается и Docker перезапускается снова. Контейнер, который на такой сети создаёт форма, копирует Duplicate или пересоздаёт Recreate, идёт без сторожа. Движок rootless до интерфейсов хоста не достаёт, сторож ему не нужен. У Podman нет daemon.json, а rootless Docker держит свой в `~/.config/docker` входа и перезапускается командой `systemctl --user restart docker`; вкладка правит только файл системного Docker и в обоих случаях так и говорит.

Проверено в контейнерах LXC с Arch Linux (Docker 29.9.3, Compose 5.7.1) и Fedora 44 (Podman 5.8.9, podman-compose 1.6.0): контейнеры создавались из формы, правились, пересоздавались и удалялись, стек из двух служб поднимался, правился и опускался, поды, том через служебный контейнер, сети с алиасами, daemon.json под сторожем (12,8 секунды вместе с перезапуском Docker). Push в реестр, pull из частного реестра с сохранённым логином, rootless Docker, Podman входа не под root и macvlan на интерфейсе сессии на настоящем хосте не проверялись.

### Остальные устройства

Выберите «Другое устройство». Для Linux подойдёт SSH. UPnP и TR-064 находят устройство по порту 1900 (у FRITZ!Box описание на порту 49000) и работают только на чтение.

SNMP v2c читает интерфейсы, адреса, маршруты, ARP, соседей и хранилище в отдельные окна: community вводится в поле «Community», его текст не скрывается, а по умолчанию там `public`; поля пользователя нет. Для SNMP v3 нужны имя пользователя и пароли.

Когда главное меню появилось, программа обходит агента так же, как `snmpwalk`: деревья mib-2 (1.3.6.1.2.1), enterprises (1.3.6.1.4.1) и модулей SNMP (1.3.6.1.6.3). Обход занимает не больше 12 секунд и 20 000 объектов, из каждой колонки читает 20 строк, из каждого незнакомого поддерева 500 объектов; остальное окна дочитывают, когда их открывают. Пока обход идёт, окна главного меню уже работают; когда он закончился, в меню появляется группа «MIB» с окном на каждый модуль MIB (IF-MIB, Q-BRIDGE-MIB, POWER-ETHERNET-MIB и так далее): вкладка на каждую таблицу и форма на каждую группу одиночных значений. То, что уже есть в главном меню (интерфейсы, адреса, маршруты, ARP, хранилище, имя системы), там не повторяется. Имена, типы и списки значений берутся из встроенного словаря из 30 стандартных модулей и модулей net-snmp; значения показаны так, как их читает человек: состояния словами, время длительностью, MAC- и IP-адреса как адреса, «да» и «нет». Окно группы «MIB» читает из таблицы не больше 1000 строк и обновляется раз в 10 секунд.

Поддерево, которого словарь не знает, например собственные объекты производителя под enterprises, показывается окном с именем производителя (MikroTik, Cisco, Huawei, …): строка на объект — OID внутри поддерева, тип и значение, не больше 2000 строк.

Для записи нужна community или пользователь с правом записи. Менять можно любую колонку, которую словарь отмечает как read-write или read-create; все изменения одной строки уходят одним запросом, и агент применяет его целиком или не применяет вовсе. Строки добавляются и удаляются в таблицах с колонкой RowStatus (VLAN из Q-BRIDGE-MIB, получатели SNMP, community, представления VACM): у новой строки сначала задаётся индекс (для таблицы, пронумерованной одним числом, окно предлагает следующий свободный номер), и программа отправляет createAndGo, а агенту, который собирает строку по шагам, — createAndWait, значения и active; строку, которую агент не принял, программа удаляет обратно. В таблицах без RowStatus строки удаляются только там, где стандарт задаёт для этого значение, например `invalid` у dot1dStaticStatus. Значение незнакомого OID меняется в том типе, который сообщил агент; счётчики не записываются никогда. У таблиц SNMP нет порядка строк, поэтому строки не перемещаются. Отката, как у Safe Mode, нет: неверная правка таблиц VACM, USM или community может закрыть программе доступ к агенту.

## Безопасность

Если роутер сменил сертификат или ключ SSH, программа сообщит об этом: отпечатки принятых сертификатов и ключей она запоминает. Протоколы без шифрования помечены в окне подключения и в главном окне. В «Настройках» есть пункты «Скрывать пароли и ключи» (в таблицах, диалогах и журнале они будут точками, значение показывает глаз в поле) и «Спрашивать перед удалением с роутера».

### Safe Mode

Safe Mode защищает от правки, после которой роутер перестал отвечать. Как он устроен, зависит от роутера.

На RouterOS нажмите Safe Mode в верхней панели. Пока он включён, при потере связи роутер сам вернёт прежние настройки. Кнопка превращается в меню со счётчиком правок: «Сохранить изменения» оставляет их, «Откатить изменения» отменяет. Если закрыть соединение, не выбрав, программа спросит, оставить ли правки.

На VyOS кнопка включает commit-confirm для каждой правки. Если после правки программа осталась без связи, VyOS примерно через минуту перезагрузится с конфигурацией, сохранённой до неё.

На OpenWrt, OPNsense и pfSense вместо Safe Mode в панели кнопка «Применить»: она применяет сделанные правки. У OpenWrt применение идёт через `uci apply` с откатом, и если после него связь пропала, роутер возвращает прежнюю конфигурацию. У OPNsense 24.7 откатываются правила файрвола, а в API версии 26.7 отката нет. У pfSense отката нет совсем. Где способа отката нет, программа так и пишет.

## Браузерная версия

Браузер не умеет сам открывать соединения с роутерами, поэтому между ним и роутером стоит шлюз. Он хранит сохранённые роутеры и их пароли и подключается к роутерам вместо страницы.

**Из приложения на компьютере.** «Настройки», «Доступ из браузера…». Задайте пароль (вход под именем `admin`), выберите порт и нажмите «Открыть доступ». Окно покажет адреса компьютера и отпечаток сертификата; для телефона есть QR-код. Откройте адрес в браузере телефона или другого компьютера той же сети. Браузер один раз предупредит о самоподписанном сертификате: сверьте его отпечаток SHA-256 с тем, что написано в окне, и продолжайте. Пока доступ открыт, порт виден в заголовке окна, а при следующем запуске приложение откроет его снова. Галочка «Любые адреса, не только локальные сети» нужна для доступа из-за пределов домашней сети (через проброшенный порт или VPN); тогда шлюз каждый раз спрашивает код приложения-аутентификатора (Google Authenticator, Aegis, 2FAS и подобные).

**Отдельным шлюзом.** Архив шлюза (`NetworkHelm-gateway-<версия>-windows-x64.zip` или `-linux-x64.tar.gz`) распаковывается и запускается без установки Java: `networkhelm-gateway.bat` на Windows, `./networkhelm-gateway.sh` на Linux. Пароль первого запуска виден один раз в окне консоли или в журнале. Если вы его потеряли, задайте новый параметром `--reset-password`. Шлюз можно запустить и как jar (нужна Java 17 или новее): `java -jar NetworkHelm-gateway-<версия>.jar`; адрес образа Docker, если он выпущен, указан в описании релиза. Дальше откройте `https://<адрес компьютера>:8443`. По умолчанию шлюз отвечает только локальным сетям; параметр `--public` открывает его для любых адресов и включает обязательный код, `--code` включает код и для локальной сети.

**Прямо на роутере OpenWrt.** Роутер с LuCI может отдавать страницу сам и ходить только к себе через `/ubus`; терминала и файлов в такой странице нет.

Подробнее о шлюзе (все параметры, Docker, контейнер на роутере с RouterOS, служба systemd) в [server/README.ru.md](server/README.ru.md).

**Страница с демонстрацией.** https://networkhelm.vasmarfas.com/ показывает интерфейс на вымышленных роутерах и вымышленном Linux-хосте. Шлюза у неё нет, а страница в браузере умеет только HTTP, так что до большинства настоящих роутеров она не дотянется. RouterOS тут не помогает: его REST API не шлёт заголовки CORS и на предварительный запрос отвечает 503 (так написано на странице MikroTik о REST API), так что страница не вызовет его даже по HTTPS с доверенным сертификатом. Direct Sockets в Chrome, которые дали бы странице настоящий TCP, открыты только изолированным контекстам вроде установленных Isolated Web Apps, а обычным страницам нет. Как устроена такая страница и что она умеет, написано в [app/webApp/README.ru.md](app/webApp/README.ru.md).

## Сетевые инструменты

Кнопка «Сетевые инструменты» в окне подключения и гаечный ключ в верхней панели роутера открывают четырнадцать инструментов. Они работают на этом компьютере или телефоне, а не на роутере.

| Инструмент | Что делает | Где работает |
|---|---|---|
| Пинг | Эхо-запросы через системный `ping` (на Android — `/system/bin/ping`, root не нужен; на iOS — ICMP-сокет, которому не нужны права) или, вторым способом, время установки TCP-соединения с портом (по умолчанию 443). Количество или «до остановки», интервал, таймаут, размер пакета, TTL, флаг «не фрагментировать» и принудительный выбор IPv4 или IPv6; показан адрес, в который превратилось имя. График последних 100 времён ответа (потерянный ответ — красная полоса), последние 20 ответов, отправлено, получено, потеряно в процентах, минимум, среднее, максимум и джиттер (отклонение времён от среднего). «Найти MTU пути» шлёт эхо разного размера с этим флагом и подбирает наибольший пакет, который проходит (только IPv4, от 576 до 1500 байт) | Компьютер, Android, iOS |
| Трассировка | Тот же `ping` с TTL от 1 до 30; у каждого узла адрес, имя и время. Имя — обратный запрос через системный резолвер: он идёт после того, как узел показан, ждёт не больше 2,5 с и отключается флажком. Останавливается на цели или после восьми молчащих узлов подряд | Компьютер, Android, iOS |
| Сканер портов | TCP-соединения со списком или диапазоном портов одного хоста (`22,80,443`, `1-1024`), по умолчанию 64 одновременно и 800 мс на каждое; порт, который не соединился, показан как закрытый или фильтруемый | Компьютер, Android, iOS |
| Сканер сети | Проверяет диапазон: `192.168.1.0/24`, `192.168.1.10-100`, `192.168.1.10-192.168.1.99` или адрес с маской, не больше 4096 адресов (адрес сети и broadcast подсети не проверяются). Начинает с /24 этого устройства, а если сетей несколько, предлагает список. На каждый адрес идёт эхо-запрос (по 48 адресов одновременно) и TCP-соединения с портами 22, 53, 80, 139, 443, 445, 5000, 8080, 8291 и 62078; узел, который ответил на что-либо из этого, попадает в список с именем, MAC-адресом, производителем, временем ответа и открытыми портами. MAC-адреса берутся из таблицы ARP этого устройства; узел, который есть в таблице, но не ответил ни на одну проверку, тоже показан. iOS и Android 10 и новее закрывают таблицу от приложений, и там в списке нет колонок MAC-адреса и производителя | Компьютер, Android, iOS |
| DNS-запрос | A, AAAA, MX, NS, TXT, CNAME, PTR, SOA, SRV и CAA по UDP у Cloudflare, Google, Quad9, Яндекса или у сервера, который вы впишете; обрезанный ответ запрашивается повторно по TCP. IP-адрес ищется как PTR | Компьютер, Android, iOS |
| Whois | Две вкладки. RDAP спрашивает реестр по HTTPS о домене, IP-адресе, сети в записи CIDR или номере AS и показывает статус, даты, DNS-серверы, регистратора и контакты, которые реестр открывает, строками; исходный JSON включается одной галочкой. Сервер берётся из файлов IANA на data.iana.org, если в них его нет, вместо него спрашивается rdap.org. Порт 43: спрашивает whois.iana.org, идёт по его ссылке в реестр и, если реестр назовёт регистратора, к нему; сервер, который отказал, оставляет на экране то, что успел прислать, и назван под текстом | RDAP: компьютер, Android; порт 43: компьютер, Android, iOS |
| Сведения об IP | Адрес, имя хоста или пусто (ваш публичный адрес). Показывает адреса, в которые превращается имя, обратное имя, AS, префикс, страну и реестр из DNS-сервиса Team Cymru, запись о сети из RDAP с контактом для жалоб, а также местоположение и провайдера с ipwho.is (с ipapi.co, если тот не ответил); для вашего адреса ещё и адрес другого семейства с ipify. Каждый блок называет хост, к которому обращался; сбой одного блока не мешает остальным | Компьютер, Android |
| Тест скорости | Задержка (медиана и джиттер по пяти запросам), приём и отдача по четырём параллельным соединениям с speed.cloudflare.com или с другим сервером, у которого те же /meta, /__down и /__up; первые полсекунды фазы не считаются, следующие 8 с считаются, цифра на экране меняется по ходу. «Стоп» обрывает соединения | Компьютер, Android |
| Wake-on-LAN | Отправляет magic-пакет на MAC-адрес широковещательным UDP (по умолчанию 255.255.255.255, порт 9) | Компьютер, Android, iOS с разрешением multicast |
| Калькулятор подсетей | Для IPv4 — сеть, маска, wildcard, broadcast, первый и последний хост, число хостов, класс и двоичная запись; для IPv6 — сеть, первый и последний адрес и их число. Диапазон (`192.168.1.10-192.168.5.110` или `192.168.1.10-100`, где число — последний октет) даёт первый и последний адрес, их число, наименьший набор блоков CIDR, который покрывает диапазон точно, и наименьшую сеть вокруг него | Везде |
| Разбиение подсетей | Три режима. «Равные» делит сеть (или диапазон, который ровно одна сеть) на части по их числу (округляется вверх до степени двойки) или по префиксу; в таблице до 1024 частей. VLSM даёт каждому числу хостов свой блок, от большего к меньшему, внутри сети или диапазона; блок не меньше /30. «Суммаризация» сводит список сетей и диапазонов, по одному в строке или через запятую, в наименьший набор блоков CIDR | Везде |
| Время передачи | По двум из трёх величин — размер, скорость, время — считает третью: размеры от Б до ТиБ (десятичные и двоичные), скорости от бит/с до ГБ/с, время в часах, минутах и секундах. Накладные расходы в процентах — доля скорости, которая не несёт данных. Для известного размера под результатом показано время при 10 Мбит/с, 100 Мбит/с и 1 Гбит/с | Везде |
| Справочник портов | 109 известных портов TCP и UDP с протоколом, сервисом и коротким описанием на языке интерфейса. Фильтр понимает начало номера, часть названия сервиса, протокол или слово из описания. Сканер портов называет открытые порты по тому же списку | Везде |
| Производитель по MAC | Ищет производителя во встроенном реестре IEEE (58 623 блока на 2026-09-25); выигрывает самый длинный префикс | Везде |
| IP ↔ HEX | Переводит адреса IPv4 в значение опции DHCP в шестнадцатеричном виде, как его принимает RouterOS (`10.103.0.250` → `0x0A6700FA`); с кодом подопции добавляет код и длину, как требует опция 43 (`1` даёт `0x01040A6700FA`). Шестнадцатеричное значение читается обратно: адреса, подопции в виде код-длина-значение и текст | Везде |

Браузер не открывает сокеты, поэтому на странице есть калькулятор, разбиение подсетей, справочник портов, время передачи, поиск по MAC и IP ↔ HEX. На iOS эхо-запросы пинга, трассировки и сканера сети идут через ICMP-сокет, которому не нужны права.

RDAP, сведения об IP и тест скорости шлют запросы на сторонние хосты, которые перечислены строкой под их формой. Им нужен HTTPS с проверкой сертификата системой, он есть на компьютере и в Android; на iOS из трёх остаётся только whois по порту 43, в браузере ни одного.

Сканирование шлёт много пакетов, поэтому запускайте его только в сетях, которыми вы управляете. На Android 10 и новее таблица ARP закрыта для приложений: MAC-адресов там не будет, а узлы, которые отвечают только на ARP, не найдутся. У MAC-адреса с битом «назначен локально», которым телефоны прячут устройство, нет производителя, он помечен как «случайный или локальный».

## Внешний вид

В настройках в списке «Тема» три темы. Modern стоит по умолчанию: плоские элементы и раскладка WinBox 4. Legacy повторяет WinBox 3 с объёмными кнопками и вкладками в рамке и остаётся светлым, пока в «Вид» не выбран тёмный. Material сделан по Material Design 3: кнопки-капсулы, скруглённые окна с тонкой рамкой, тональное выделение текущего пункта, заголовок активного окна в оттенке акцента. Размеры рассчитаны на мышь: строки таблиц 26 dp против 24 у Modern, поля и заголовки окон 32 dp; на телефоне любая тема вырастает до 40 dp под палец. «Строки таблиц» в тех же настройках прибавляют каждой строке таблицы до 8 dp или убирают 2. «Комментарии в таблицах» ставят комментарий строки над ней, в столбец или убирают совсем во всех таблицах. Кнопка комментариев в окне таблицы задаёт этой таблице свой режим и подсвечена, пока он есть; пункт «Как в настройках» в начале её меню возвращает таблицу к общей настройке, а смена настройки возвращает к ней все таблицы. «Цвет» выбирает один из восьми акцентов, и Material строит из него и светлую, и тёмную палитру. На Android 12 и новее «Цвета системы» вместо этого берут палитру, которую Android строит по обоям. «Вид» выбирает между светлым, тёмным и настройкой системы; Modern и Material повторяют систему, пока это не изменено.

Окно настроек открывает свои таблицы кнопками, как в WinBox: Static, Cache, Adlist и Forwarders у IP › DNS открывают одно окно «DNS» с вкладкой на каждую таблицу, а следующая кнопка переключает это окно на свою вкладку. Настройка «Таблицы окна настроек — вкладками этого окна» ставит их вкладками окна настроек, и окно вырастает до высоты всей формы; так же устроены SNMP, NTP, UPnP, NAT-PMP, RoMON и Accounting в RouterOS 6. Окна, открытые до переключения, остаются как были.

Группа левого меню открывается панелью сбоку от меню. «Раскрывать группы левого меню вниз» в настройках показывает её окна списком под названием, как веб-интерфейс Keenetic, и делает меню на 40 dp шире, чтобы их названия помещались; в узком окне список под названием всегда.

Сообщения самой программы — на языке интерфейса: с русским интерфейсом ошибка подключения, проверки поля или отказа окна написана по-русски. Текст, который прислал роутер, показывается как есть.

Передачи окна «Файлы» и сессия терминала принадлежат подключению, а не окну. Свёрнутое или закрытое другими окно их не останавливает; закрытое окно «Файлы» оставляет передачи идти, и открытое снова показывает их очередь. Останавливает их отключение от роутера.

## Если что-то не получается

| Что вы видите | В чём дело | Что делать |
| --- | --- | --- |
| «… не принимает подключения на порт N: сервис выключен или порт закрыт» | служба на роутере выключена или порт закрыт файрволом | включите службу (на RouterOS, например, `/ip service enable api`) или выберите другой протокол; серым в списке помечены порты, которые не ответили |
| «… не отвечает» | неверный адрес, нет маршрута или файрвол молча отбрасывает пакеты | проверьте адрес, пропингуйте роутер, убедитесь, что вы в той же сети; если роутер за другим роутером, используйте поле «Через роутер» |
| «Не удалось найти …» | имя не удаётся преобразовать в адрес | впишите IP-адрес |
| «Роутер не принял вход: …» | неверный логин или пароль, либо у пользователя нет прав на эту службу | проверьте их и, на RouterOS, группу пользователя |
| «… и NetworkHelm не договорились о TLS …» | на RouterOS включён API-SSL, но у службы нет сертификата | выберите «API (8728)», подключитесь и в окне «Подготовить роутер» выпустите сертификат |
| «… не ответил по SNMP» | community неверная или у неё нет права чтения (свитч считает такой запрос «illegal operation for community name supplied»), агент выключен или закрыт UDP 161 | проверьте community на агенте: она должна существовать с правом чтения и пускать ваш адрес; SNMP v2c должен быть включён |
| «the SNMP agent answered notWritable for …» (или noAccess, readOnly, authorizationError) | объект на этом агенте только для чтения, или у community или пользователя нет права его писать | возьмите community или пользователя с правом записи и представлением, в которое входит объект |
| «the SNMP agent answered inconsistentValue for …» (или wrongValue, wrongLength, noCreation) | агент не принимает это значение или эту строку: у новой строки не заполнена обязательная колонка, индекс занят, значение вне допустимого диапазона | заполните остальные колонки строки, возьмите другой индекс, проверьте допустимые значения в документации устройства |
| «Android не пускает NetworkHelm в локальную сеть» | не выдано разрешение | в настройках приложения Android разрешите «Устройства поблизости» |
| «Соединение потеряно после отправки команды. …» | связь пропала в момент правки | сначала проверьте роутер: команда могла выполниться, и повтор сделает её дважды |
| «Соединение с роутером потеряно, переподключение…» | связь пропала или роутер перезагрузился; на телефоне система ещё и закрывает соединения приложения в фоне | подождите: сеанс вернётся сам, открытые формы сохранят введённое; на телефоне после возврата в приложение это занимает несколько секунд |
| «Загрузка… 2187 из 34998» внизу списка | по TCP 8291, SSH и REST таблица больше 2 000 строк идёт порциями, чтобы роутеру не пришлось держать её в памяти целиком; в локальной сети 30 000 строк занимают около 10 секунд по REST и 40 по TCP 8291 | подождите: список готов, когда счётчик сменится числом строк |
| Слабый роутер (MIPS, например hAP lite или RB951) около минуты загружен после первого входа | программа один раз читает через консоль роутера описания окон этой версии RouterOS и хранит их для следующих входов | дождитесь конца первого входа, следующие его не повторяют. По TCP 8291 скорости интерфейсов и полоса ресурсов идут из окон порта WinBox, а это стоит роутеру намного меньше консоли |
| «Не загружено» и кнопка «Повторить» под списком | строки не пришли, причина написана рядом с кнопкой | нажмите «Повторить» или F5 |
| Роутер перестал отвечать сразу после ввода адреса | его защита от подбора паролей сочла проверку портов попыткой входа | дождитесь конца блокировки и выключите проверку в «Настройках» |
| «Браузер заблокировал запрос …» | страница в браузере умеет только HTTP, а RouterOS не шлёт заголовки CORS | откройте приложение через шлюз или подключайтесь приложением |
| Программа не запускается | на компьютере причина записана в файл `NetworkHelm-startup-error.log` во временной папке | возьмите файл (`%TEMP%` в Windows, `/tmp` в Linux) и приложите к обращению вместе с версией системы |
| Окно закрывается после сообщения об ошибке | ошибка записана в файл `NetworkHelm-error.log` в той же временной папке, полный путь есть в сообщении | приложите этот файл к обращению |

Остальное можно спросить в [трекере задач](https://github.com/vasmarfas/networkhelm/issues). Адреса, пароли и ключи в обращения не вставляйте.

## Где лежат данные

Сохранённые роутеры, настройки и раскладки таблиц программа хранит в своей папке данных. Пароли и ключи, которые вы попросили запомнить, лежат в защищённом хранилище системы: защита данных Windows (DPAPI), связка ключей в macOS и iOS, Secret Service в Linux, Android Keystore в Android. Если системного хранилища нет, программа шифрует их сама, и такая защита слабее. Всё подробно описано в [privacy-policy.md](privacy-policy.md).

На компьютере можно запустить несколько копий программы, как WinBox, по окну на роутер. Перед каждой записью копия перечитывает файл и кладёт свою правку поверх того, что в нём сейчас: роутер, сохранённый в одной копии, не пропадёт из-за сохранения в другой, и то же с настройками, темами, сниппетами, таблицами, туннелями и паролями. Роутеры и пароли, которые сохранила другая копия, появляются, когда открывается окно подключения; настройки, которые поменяла другая копия, эта показывает после перезапуска.

### Синхронизация

Синхронизация держит одинаковыми сохранённые роутеры и остальную вашу работу на компьютерах, телефонах и странице на GitHub Pages. Пока вы её не настроили, она выключена, и программа ничего для неё никуда не отправляет. Настроенная, она отправляет только зашифрованные файлы и только в выбранные вами сервисы: сервера разработчика между вашими устройствами нет.

Что синхронизируется: сохранённые роутеры, доверенные отпечатки сертификатов и ключей хостов, настройки, не зависящие от устройства (язык, тема, тёмный режим, акцентный цвет и системные цвета, комментарии в таблицах, вопрос перед удалением с роутера, скрытие паролей, проверка новых версий), темы, сниппеты терминала, шаблоны Docker, в `.env` которых остаются имена переменных без значений, именованные рабочие области и туннели каждого роутера; в «Что синхронизировать» у каждого вида своя галочка. Пароли и ключи роутеров (пароли, ключи SSH и их парольные фразы, ключи приватности SNMP) уходят только с галочкой «Пароли и ключи роутеров», которая сначала снята; на другом устройстве они сразу ложатся в его защищённое хранилище. На каждом устройстве остаются масштаб, распознавание устройства при вводе адреса, вид таблиц и меню, полоса ресурсов, раскладка окна подключения и число строк терминала, а также раскладки таблиц, рабочая область без имени, вид меню роутера, окно программы и кэш описаний меню.

Настройки → «Синхронизация…» → «Настроить…» начинается с выбора сервиса:

- папка на компьютере, на Android или в «Файлах» на iOS, которую одинаковой держит Syncthing или клиент Dropbox, OneDrive, Яндекс Диска, Облака Mail.ru, Nextcloud, iCloud Drive; каждое устройство выбирает папку само, программа работает только в её подпапке `networkhelm-sync`;
- Dropbox, папка программы Apps/NetworkHelm, кроме неё программа там ничего не видит: вход в браузере, на телефоне браузер сам возвращается в программу; страница входит только по адресу https://networkhelm.vasmarfas.com/;
- Google Диск, скрытая папка программы: место на диске она занимает, но среди файлов не видна; на компьютере, Android и iOS, на странице нет: без своего сервера Google странице вход не даёт;
- Яндекс Диск, папка программы Приложения/NetworkHelm: везде, в том числе на странице по тому же адресу;
- iCloud, контейнер CloudKit программы, вход с Apple ID: везде; компьютер и Android входят через страницу по тому же адресу, и она возвращает ответ в программу;
- WebDAV: Nextcloud, ownCloud, Synology, Яндекс Диск (`https://webdav.yandex.ru`) или Облако Mail.ru (`https://webdav.cloud.mail.ru`) — с паролем приложения, созданным для NetworkHelm;
- S3: MinIO, Yandex Object Storage, Selectel или AWS — с ключом только на этот бакет;
- Git: закрытый репозиторий на GitHub (детальный токен с правом Contents: Read and write), GitLab (токен проекта со скоупом `api` и ролью Developer, Maintainer, если ветка защищена) или Gitea (`write:repository`) — с токеном только на этот репозиторий;
- ваш шлюз NetworkHelm, сервер или десктопная программа с включённым доступом из браузера: адрес, пользователь, пароль и код приложения-аутентификатора, за которые устройство получает токен.

Адрес сервиса должен начинаться с https://. Сервер, сертификату которого система не доверяет, спрашивает об отпечатке так же, как роутер, поверх любого окна, но только если это ваш собственный сервер: IP-адрес, локальное имя вроде nas.local или порт не 443, как у шлюза. Общедоступный сервис с недоверенным сертификатом отвергается: значит, между вами и ним кто-то стоит. Если в системе нет защищённого хранилища для ключей, окно говорит, что программа шифрует их сама.

На пустом сервисе создаётся новое хранилище. Его пароль — не короче 12 знаков, не из списка самых частых паролей, и подбор по оценке в духе zxcvbn должен требовать больше 10^10 попыток; строка под полем говорит, что делает пароль слабым. При 256 МиБ памяти на попытку 10^10 попыток — около года работы одной видеокарты. «Придумать фразу» даёт пять слов из списка EFF, около 64 бит, такому перебору недоступных. «Повышенная защита» добавляет секретный ключ на 128 бит, который показывается один раз — 26 букв и цифр группами по четыре: без него копию хранилища не подобрать вовсе, и новому устройству нужен и он, если оно не берёт код устройства, уже входящего в хранилище. Если забыть пароль и потерять все устройства, данные не открыть: ключа у сервиса нет. Ключ получается из пароля через Argon2id, 256 МиБ памяти и 3 прохода — на компьютере несколько секунд, на старом телефоне дольше; пароль считается одним и тем же, как бы система ни составляла его буквы. Каждый файл шифруется XChaCha20-Poly1305 и проверяется при чтении: файл, изменённый на сервисе, подложенный на место другого или возвращённый из прошлого, не принимается. Сервис видит, что у вас есть хранилище NetworkHelm, сколько устройств в него пишет, когда они пишут, и его размер с точностью до 4 КиБ.

Если на сервисе уже есть хранилище, второе устройство подключается к нему паролем. Второй путь — код: на устройстве, уже входящем в хранилище, «Показать код…» ещё раз спрашивает пароль и на 60 секунд показывает QR-код и тот же код текстом под ним; текст нельзя выделить, поэтому в буфер обмена он не попадает. Код открывает все ваши данные, не показывайте его никому. На новом устройстве «У меня есть код с другого устройства» принимает текст, а телефон сканирует QR-код камерой и спрашивает разрешение на камеру только в этот момент. Перед подключением окно называет сервис и устройства хранилища: подключайтесь, только если они ваши. В коде папки самой папки нет, новое устройство выбирает свою; код WebDAV, S3, Git или шлюза несёт вход устройства, которое его показало, поэтому сервис видит один вход на оба устройства, и его отзыв останавливает оба. Так же подключается устройство, которому не хватает памяти на Argon2id.

Раунд идёт при запуске, через две секунды после правки, сразу при возвращении окна на передний план, раз в минуту, пока окно впереди, и раз в 15 минут, пока оно позади. Шлюз сообщает об изменении сразу; с остальными сервисами правка с другого устройства появляется в течение минуты, пока программа на переднем плане. Правки без сети ждут и уходят со следующим раундом. Каждый роутер, пароль, сниппет и настройка сливаются отдельно и по полям: если на одном устройстве поменяли порт роутера, а на другом его комментарий, остаются обе правки, а из двух правок одного поля побеждает поздняя. Удаление хранится 180 дней, и устройство, вернувшееся после более долгого отсутствия, не возвращает удалённое за это время. Из двух копий программы на одной папке данных синхронизирует одна, правки другой идут через неё.

Окно синхронизации показывает сервис, как прошёл последний раунд, и кнопку «Синхронизировать». В «Устройствах» — это устройство, которое можно переименовать, и остальные с системой, версией программы и временем, когда каждое последний раз было на связи; устройство обновляет свою строку с каждым записанным состоянием, после смены имени, системы или версии и раз в сутки, а устройство, чьи файлы ушли с сервиса, пропадает из списка. «Отключить…» у другого устройства спрашивает текущий и новый пароль и создаёт новый ключ данных: отключённое устройство не читает ничего, что записано после, его файлы уходят с сервиса, а остальные устройства один раз спросят новый пароль. Прочитанное раньше остаётся у него, а его вход в сервис отзывается в настройках самого сервиса. «Сменить пароль…» тоже спрашивает текущий пароль. Ключ данных остаётся прежним, и остальные устройства работают без нового пароля; «Сменить и ключ данных» — для пароля, который мог узнать кто-то ещё: прежняя копия хранилища в истории сервиса или клиента синхронизации открывается прежним паролем. «Я забыл пароль» задаёт новый пароль без текущего, а это может любой, кто пользуется устройством; вместе с паролем меняется ключ данных, остальные устройства останавливаются и спрашивают новый пароль, так что подмена не пройдёт незамеченной. При повышенной защите каждый новый ключ данных приходит с новым секретным ключом, который показывается один раз; он нужен и устройству, которое спрашивает новый пароль. «Сменить сервис…» переносит хранилище целиком с теми же ключами; перенесите и остальные устройства или дайте им код. «Добавить место…» держит ещё одну полную копию хранилища в другом сервисе, выбранном как в мастере, и это устройство поддерживает все копии одинаковыми: устройства разных мест получают данные друг друга через него, а новый пароль или ключ, сделанные на устройстве одного места, доходят до хранилища остальных с его следующим раундом. Место, которое не ответило, видно под состоянием строкой «Не синхронизировано с» и причиной, остальные места идут дальше. «Убрать» рядом с местом удаляет из него файлы этого устройства; хранилище и файлы остальных устройств там остаются для тех, кто им пользуется. Облако может быть только одним местом. «Выключить…» вверху стирает с этого устройства ключи и вход в сервис и оставляет на нём данные. С галочкой «Удалить и хранилище с сервиса» останавливаются все устройства, и хранилище не вернуть; данные остаются на каждом устройстве.

Если два устройства доверяют разным ключам для одного адреса и порта, синхронизация не выбирает: каждое устройство оставляет свой, а «Спорные отпечатки» показывают оба. Два роутера за одним адресом, например 192.168.88.1 дома и на работе, тоже дают такой спор, потому что отпечаток хранится на адрес и порт; без ответа у каждого устройства остаётся свой ключ. «Взять другой» кладёт сюда ключ другого устройства; «Оставить этот» отправляет этот ключ остальным, и вопрос переходит к ним. Файл, который сервис вернул из прошлого или который записан прежним ключом, показывается под состоянием как «Не принят файл» с причиной. Хранилище, которое сервис вернул из времени до смены ключа — из копии или своей истории, — останавливает все устройства: устройство с более новым ключом говорит об этом, остальные ничего не пишут, пока новый пароль не откроет хранилище. «Сменить пароль…» → «Я забыл пароль» на устройстве, которое меняло ключ последним, кладёт на его место хранилище с новым ключом.

Рядом с настройками, в панели инструментов роутера и в шапке окна подключения, облако с галочкой значит «синхронизировано», две круговые стрелки — идёт раунд, красное облако с восклицательным знаком — сбой; значок открывает окно. Пока синхронизация выключена, значка нет.

Страница на GitHub Pages синхронизируется так же, как программа, только без папки. Страница достаёт лишь до сервиса, который разрешает страницам с других адресов читать его ответы (CORS). Шлюз NetworkHelm пускает страницу с GitHub Pages, но закрепить сертификат шлюза страница не может: сначала откройте адрес шлюза во вкладке браузера и примите сертификат там. Сервер WebDAV или бакет S3 пускает страницу, когда владелец разрешил её адрес; об обоих окно предупреждает при выборе сервиса. Ключи и запомненные пароли роутеров лежат в локальном хранилище браузера под ключом WebCrypto, который страница не может выгрузить, и переживают перезагрузку. Копия профиля браузера их не открывает, а скрипт с того же адреса откроет, и адрес страницы общий у всех сайтов GitHub Pages одной учётной записи; пока страница открыта, ключи в её памяти. Телефон фотографирует код своей камерой, и браузер находит код на снимке (Chromium на Android, ChromeOS и macOS); в остальных браузерах введите текст. На странице, которую отдаёт шлюз или роутер, синхронизации нет: она работает с данными этого узла. Данные, которые показывает шлюз десктопной программы, синхронизирует сама программа, а сервер-шлюз держит свои роутеры у себя и участвует только как сервис для остальных устройств.

Синхронизация появилась в 1.4.0. Именованные рабочие области и туннели, сохранённые до неё, уходят на другие устройства, после того как вкладку их роутера откроют в 1.4.0, а открытая вкладка показывает их изменение с другого устройства, после того как её откроют заново. Версия, не знающая вида данных из более новой, передаёт его дальше нетронутым; хранилище, которому нужна более новая версия, останавливается с просьбой обновить программу. Шлюз выдаёт каждому вошедшему устройству свой токен, но отзывает их только все сразу, новым паролем шлюза. Git хранит каждую запись как коммит, поэтому репозиторий каждый раз растёт на размер состояния. Проверено: две копии программы с разными папками данных через сервер WebDAV, сервисы — на Apache mod_dav, MinIO и Gitea, телефон Android вошёл по коду и обменялся роутерами в обе стороны; iOS, камера телефона и страница в браузере для этого выпуска на настоящих устройствах не проверялись.
