# Руководство

Здесь собрано то, что нужно для начала: как установить программу, как подключиться к роутеру, что включить на самом роутере и что делать, если не получается. Описаний каждого окна нет. Меню и поля программа читает у роутера, а смысл настроек объясняют производители; для MikroTik это документация RouterOS. О проекте в целом написано в [README.ru.md](README.ru.md).

**English:** [GUIDE.md](GUIDE.md)

## Установка

### Windows

Запустите установщик (`windows-setup.exe`) или переносной файл (`windows-portable.exe`, установки не требует). Если у файла нет подписи издателя, Windows покажет окно «Система Windows защитила ваш компьютер»: нажмите «Подробнее», затем «Выполнить в любом случае».

Переносной файл при первом запуске распаковывается в `%LOCALAPPDATA%\NetworkHelm\portable\<версия>` (около 200 МБ) и хранит настройки в папке `NetworkHelm data` рядом с собой. Если установщик или переносной файл пишет, что программа не поддерживает эту версию Windows, у вас Windows 7, 8 или 8.1. Для них есть файлы с пометкой `legacy`.

### macOS

Откройте DMG и перетащите NetworkHelm в «Программы». Если программа не подписана Apple, при первом запуске macOS откажется её открыть. Откройте «Системные настройки», «Конфиденциальность и безопасность», найдите сообщение о NetworkHelm и нажмите «Всё равно открыть». Когда macOS спросит про доступ к локальной сети, разрешите его: без этого программа не достанет роутеры вашей сети.

### Linux

DEB и RPM ставятся менеджером пакетов:

```bash
sudo apt install ./NetworkHelm-<версия>-linux-amd64.deb
sudo dnf install ./NetworkHelm-<версия>-linux-x86_64.rpm
```

AppImage не ставится: сделайте файл исполняемым (`chmod +x`) и запустите. Он монтируется через FUSE и ждёт `fusermount` из пакета `fuse3` или `fuse`; без FUSE запускайте его с ключом `--appimage-extract-and-run`.

### Android

Скачайте APK и откройте его, Android спросит разрешение на установку из этого источника. При первом подключении разрешите программе «Устройства поблизости». Без этого Android не пускает её в локальную сеть, и вместо входа вы увидите сообщение «Android не пускает NetworkHelm в локальную сеть».

### iOS

Готового приложения нет, есть проект Xcode. На Mac с Xcode один раз выполните `tools/ios/build-ssh.sh`, затем откройте `app/iosApp` и соберите приложение на своё устройство.

Список соседей, MAC-Telnet и Wake-on-LAN работают широковещательными пакетами, а их iOS разрешает приложению отправлять и принимать только с разрешением multicast, которое Apple выдаёт по заявке. Пока его у приложения нет, вкладка «Соседи», вход по MAC-адресу и Wake-on-LAN на iOS скрыты. Когда разрешение есть, для MAC-Telnet нужен ещё MAC-адрес самого устройства, и окно подключения его просит: iOS не сообщает его приложениям, а роутер отвечает на адрес, который назвал клиент. Это «Адрес Wi-Fi» в Настройках → Wi-Fi → (i) у сети; с частным адресом он у каждой сети свой. Таблица ARP приложениям закрыта, поэтому сканер сети не показывает там MAC-адрес и производителя. Язык приложения задаётся в Настройках → NetworkHelm → Язык.

## Первое подключение

При запуске открывается окно подключения. Поля в нём такие:

| Поле | Что вписать |
| --- | --- |
| Адрес | имя или IP-адрес роутера; порт добавляют через двоеточие, если он нестандартный |
| Платформа | тип устройства; программа определяет его сама и пишет рядом «определена сама» |
| Протокол | способ подключения; серым отмечены порты, которые не ответили |
| Порт | менять нужно, только если служба на роутере слушает нестандартный порт |
| Пользователь, Пароль | учётная запись на роутере |
| Запомнить пароль | сохранить пароль в защищённом хранилище системы |
| Группа, Комментарий | для порядка в списке сохранённых роутеров |
| Через роутер | подключиться через SSH другого сохранённого роутера, если нужный недоступен напрямую |

Как только вы вписали адрес, программа почти сразу проверяет, какие порты на роутере отвечают. Она только пробует открыть соединение и читает приветствие, не входя в роутер; по ответам определяет тип устройства и выбирает протокол. Выбор можно поменять руками. У роутера с защитой от подбора паролей такая проверка может сойти за попытку входа, и он заблокирует ваш адрес. Тогда выключите её в «Настройках»: пункт «Распознавать устройство и проверять, какие протоколы отвечают, пока вводится адрес».

Нажмите «Подключиться». Кнопка «Сохранить» кладёт роутер в список на вкладке «Сохранённые», при следующем запуске его достаточно выбрать там: щелчок заполняет форму, двойной щелчок подключает. Вкладка «Соседи» показывает MikroTik, которые объявляют себя в вашей сети. Они делают это раз в 30–60 секунд, кнопка «Обновить» просит их ответить сразу. В окне шириной от 960 dp форма и списки стоят рядом на всю высоту окна; кнопка справа от вкладок уносит списки под форму и обратно. Под формой высоту между ними делит полоса: её можно перетащить, двойной щелчок возвращает форме её собственную высоту.

Если подключение идёт по протоколу без шифрования (API на порту 8728, HTTP, SNMP v2c), под полями появится предупреждение, а в главном окне метка «Без шифрования». Пароль и все данные тогда идут по сети открытым текстом, так что работать в таком режиме стоит только в доверенной сети.

Чтобы открыть конфигурацию без роутера, нажмите «Открыть файл конфигурации» или перетащите файл на окно подключения: подойдёт `/export` RouterOS, бэкап OpenWrt или файл UCI.

## Подготовка роутера

Программа ходит к роутеру через службы, которые на нём уже есть. Если нужная служба выключена или закрыта файрволом, подключиться не получится, и программа напишет, какой порт не отвечает.

### MikroTik RouterOS

Службы видны в WinBox и в консоли: `/ip service print`. Подойдёт любая из них:

| Способ | Порт | Замечания |
| --- | --- | --- |
| TCP 8291 (порт WinBox) | 8291 | через этот порт работает весь интерфейс, ни API, ни REST, ни SSH не нужны; программа выбирает его первым, если порт отвечает; вход по этому порту не работает на RouterOS 6.42, там выберите API |
| API-SSL | 8729 | шифруется; нужен сертификат: без него RouterOS отвечает анонимным TLS, которым программа не пользуется |
| API | 8728 | без шифрования |
| REST по HTTPS и HTTP | 443 и 80 | только RouterOS 7.1 и новее, службы `www-ssl` и `www` |
| MAC-Telnet | UDP 20561 | для роутера без IP-адреса; нужен MAC-адрес и общая сеть второго уровня, на iOS ещё и MAC-адрес устройства |

Для нового MikroTik логин обычно `admin`, пароль пустой или напечатан на наклейке. Если у группы пользователя нет прав на какой-то раздел меню, программа помечает его и пишет, каких прав не хватает.

Если у пользователя истёк пароль (RouterOS просит новый после `/user/expire-password`), программа сразу после входа предложит его задать. «Пропустить» — работать со старым, при следующем входе роутер спросит снова. Вопрос приходит через консоль роутера, поэтому его видно по TCP 8291, SSH и MAC-Telnet, но не по API.

Чтобы перейти на шифрование, сначала подключитесь другим способом. Если с первой попытки вы получили ошибку про TLS (API-SSL включён, а сертификата нет), выберите в списке «Протокол» вариант «API (8728)». Когда соединение откроется, щёлкните по метке «Без шифрования» в главном окне: откроется окно «Подготовить роутер». В нём четыре шага, любой можно отметить или снять, а команды выполнятся по кнопке «Применить»:

- выпустить самоподписанный сертификат и включить API-SSL (8729);
- разрешить API через туннель SSH (`forwarding-enabled=local`);
- добавить группу пользователей `networkhelm` с правами, которые нужны программе; под неё можно завести отдельного пользователя вместо `admin`;
- выключить открытый API (8728) и Telnet; пока это подключение идёт через API 8728, этот шаг недоступен, иначе оно бы оборвалось.

Дальше подключайтесь по API-SSL: отпечаток сертификата программа спросит один раз.

### OpenWrt

Выберите платформу OpenWrt. Есть два способа:

- SSH, порт 22. Нужен пароль root или ключ. На только что прошитом роутере пароль задают в LuCI, в разделе System, Administration.
- ubus по HTTP (порт 80) или HTTPS (порт 443). Нужны LuCI с модулем ubus у веб-сервера и rpcd; входят под root с его паролем.

Сверху главного окна можно переключать вид меню: «Вид OpenWrt», «Единый вид» (меню, которые у программы есть для любого роутера) и «Вид LuCI».

### OPNsense

На роутере создайте ключ API: System, Access, Users, нужный пользователь, API keys. Скачается файл с ключом и секретом. В программе в поле «Пользователь» впишите ключ, в поле «Пароль» секрет. Порт 443.

### pfSense

Нужен установленный пакет pfSense-pkg-RESTAPI версии 2: без него pfSense не отвечает на API. Войти можно двумя способами: оставить поле «Пользователь» пустым, а в «Пароль» вписать ключ из System, REST API, Keys; либо указать логин и пароль локального пользователя.

### VyOS 1.4 и новее

Нужно включить HTTP API и создать ключ: `set service https api keys id <имя> key <ключ>`, затем `commit` и `save`. В программе ключ вписывается в «Пароль», поля пользователя у VyOS нет. Каждая правка сразу применяется и сохраняется.

### Keenetic и Netcraze

Только чтение. Впишите логин и пароль веб-интерфейса, либо оставьте логин пустым, а в пароль подставьте токен доступа KeeneticOS 5.2 (раздел «Пользователи и доступ»). Эти драйверы написаны по документации, на настоящем устройстве их не пробовали.

### Остальные устройства

Выберите «Другое устройство». Для Linux подойдёт SSH. UPnP и TR-064 находят устройство по порту 1900 (у FRITZ!Box описание на порту 49000) и работают только на чтение.

SNMP v2c читает интерфейсы, адреса, маршруты, ARP, соседей и хранилище в отдельные окна: community вводится в поле «Community», его текст не скрывается, а по умолчанию там `public`; поля пользователя нет. Для SNMP v3 нужны имя пользователя и пароли.

Когда главное меню появилось, программа обходит агента так же, как `snmpwalk`: деревья mib-2 (1.3.6.1.2.1), enterprises (1.3.6.1.4.1) и модулей SNMP (1.3.6.1.6.3). Обход занимает не больше 12 секунд и 20 000 объектов, из каждой колонки читает 20 строк, из каждого незнакомого поддерева 500 объектов; остальное окна дочитывают, когда их открывают. Пока обход идёт, окна главного меню уже работают; когда он закончился, в меню появляется группа «MIB» с окном на каждый модуль MIB (IF-MIB, Q-BRIDGE-MIB, POWER-ETHERNET-MIB и так далее): вкладка на каждую таблицу и форма на каждую группу одиночных значений. То, что уже есть в главном меню (интерфейсы, адреса, маршруты, ARP, хранилище, имя системы), там не повторяется. Имена, типы и списки значений берутся из встроенного словаря из 30 стандартных модулей и модулей net-snmp; значения показаны так, как их читает человек: состояния словами, время длительностью, MAC- и IP-адреса как адреса, «да» и «нет». Окно группы «MIB» читает из таблицы не больше 1000 строк и обновляется раз в 10 секунд.

Поддерево, которого словарь не знает, например собственные объекты производителя под enterprises, показывается окном с именем производителя (MikroTik, Cisco, Huawei, …): строка на объект — OID внутри поддерева, тип и значение, не больше 2000 строк.

Для записи нужна community или пользователь с правом записи. Менять можно любую колонку, которую словарь отмечает как read-write или read-create; все изменения одной строки уходят одним запросом, и агент применяет его целиком или не применяет вовсе. Строки добавляются и удаляются в таблицах с колонкой RowStatus (VLAN из Q-BRIDGE-MIB, получатели SNMP, community, представления VACM): у новой строки сначала задаётся индекс (для таблицы, пронумерованной одним числом, окно предлагает следующий свободный номер), и программа отправляет createAndGo, а агенту, который собирает строку по шагам, — createAndWait, значения и active; строку, которую агент не принял, программа удаляет обратно. В таблицах без RowStatus строки удаляются только там, где стандарт задаёт для этого значение, например `invalid` у dot1dStaticStatus. Значение незнакомого OID меняется в том типе, который сообщил агент; счётчики не записываются никогда. У таблиц SNMP нет порядка строк, поэтому строки не перемещаются. Отката, как у Safe Mode, нет: неверная правка таблиц VACM, USM или community может закрыть программе доступ к агенту.

## Безопасность

Если роутер сменил сертификат или ключ SSH, программа сообщит об этом: отпечатки принятых сертификатов и ключей она запоминает. Протоколы без шифрования помечены в окне подключения и в главном окне. В «Настройках» есть пункты «Скрывать пароли и ключи» (в таблицах, диалогах и журнале они будут точками, значение показывает глаз в поле) и «Спрашивать перед удалением с роутера».

### Safe Mode

Safe Mode защищает от правки, после которой роутер перестал отвечать. Как он устроен, зависит от роутера.

На RouterOS нажмите Safe Mode в верхней панели. Пока он включён, при потере связи роутер сам вернёт прежние настройки. Кнопка превращается в меню со счётчиком правок: «Сохранить изменения» оставляет их, «Откатить изменения» отменяет. Если закрыть соединение, не выбрав, программа спросит, оставить ли правки.

На VyOS кнопка включает commit-confirm для каждой правки. Если после правки программа осталась без связи, VyOS примерно через минуту перезагрузится с конфигурацией, сохранённой до неё.

На OpenWrt, OPNsense и pfSense вместо Safe Mode в панели кнопка «Применить»: она применяет сделанные правки. У OpenWrt применение идёт через `uci apply` с откатом, и если после него связь пропала, роутер возвращает прежнюю конфигурацию. У OPNsense 24.7 откатываются правила файрвола, а в API версии 26.7 отката нет. У pfSense отката нет совсем. Где способа отката нет, программа так и пишет.

## Браузерная версия

Браузер не умеет сам открывать соединения с роутерами, поэтому между ним и роутером стоит шлюз. Он хранит сохранённые роутеры и их пароли и подключается к роутерам вместо страницы.

**Из приложения на компьютере.** «Настройки», «Доступ из браузера…». Задайте пароль (вход под именем `admin`), выберите порт и нажмите «Открыть доступ». Окно покажет адреса компьютера и отпечаток сертификата; для телефона есть QR-код. Откройте адрес в браузере телефона или другого компьютера той же сети. Браузер один раз предупредит о самоподписанном сертификате: сверьте его отпечаток SHA-256 с тем, что написано в окне, и продолжайте. Пока доступ открыт, порт виден в заголовке окна, а при следующем запуске приложение откроет его снова. Галочка «Любые адреса, не только локальные сети» нужна для доступа из-за пределов домашней сети (через проброшенный порт или VPN); тогда шлюз каждый раз спрашивает код приложения-аутентификатора (Google Authenticator, Aegis, 2FAS и подобные).

**Отдельным шлюзом.** Архив шлюза (`NetworkHelm-gateway-<версия>-windows-x64.zip` или `-linux-x64.tar.gz`) распаковывается и запускается без установки Java: `networkhelm-gateway.bat` на Windows, `./networkhelm-gateway.sh` на Linux. Пароль первого запуска виден один раз в окне консоли или в журнале. Если вы его потеряли, задайте новый параметром `--reset-password`. Шлюз можно запустить и как jar (нужна Java 17 или новее): `java -jar NetworkHelm-gateway-<версия>.jar`; адрес образа Docker, если он выпущен, указан в описании релиза. Дальше откройте `https://<адрес компьютера>:8443`. По умолчанию шлюз отвечает только локальным сетям; параметр `--public` открывает его для любых адресов и включает обязательный код, `--code` включает код и для локальной сети.

**Прямо на роутере OpenWrt.** Роутер с LuCI может отдавать страницу сам и ходить только к себе через `/ubus`; терминала и файлов в такой странице нет.

Подробнее о шлюзе (все параметры, Docker, контейнер на роутере с RouterOS, служба systemd) в [server/README.ru.md](server/README.ru.md).

**Страница с демонстрацией.** https://vasmarfas.github.io/networkhelm/ показывает интерфейс на вымышленных роутерах. Шлюза у неё нет, а страница в браузере умеет только HTTP, так что до большинства настоящих роутеров она не дотянется. RouterOS тут не помогает: его REST API не шлёт заголовки CORS и на предварительный запрос отвечает 503 (так написано на странице MikroTik о REST API), так что страница не вызовет его даже по HTTPS с доверенным сертификатом. Direct Sockets в Chrome, которые дали бы странице настоящий TCP, открыты только изолированным контекстам вроде установленных Isolated Web Apps, а обычным страницам нет. Как устроена такая страница и что она умеет, написано в [app/webApp/README.ru.md](app/webApp/README.ru.md).

## Сетевые инструменты

Кнопка «Сетевые инструменты» в окне подключения и гаечный ключ в верхней панели роутера открывают четырнадцать инструментов. Они работают на этом компьютере или телефоне, а не на роутере.

| Инструмент | Что делает | Где работает |
|---|---|---|
| Пинг | Эхо-запросы через системный `ping` (на Android — `/system/bin/ping`, root не нужен; на iOS — ICMP-сокет, которому не нужны права) или, вторым способом, время установки TCP-соединения с портом (по умолчанию 443). Количество или «до остановки», интервал, таймаут, размер пакета, TTL, флаг «не фрагментировать» и принудительный выбор IPv4 или IPv6; показан адрес, в который превратилось имя. График последних 100 времён ответа (потерянный ответ — красная полоса), последние 20 ответов, отправлено, получено, потеряно в процентах, минимум, среднее, максимум и джиттер (отклонение времён от среднего). «Найти MTU пути» шлёт эхо разного размера с этим флагом и подбирает наибольший пакет, который проходит (только IPv4, от 576 до 1500 байт) | Компьютер, Android, iOS |
| Трассировка | Тот же `ping` с TTL от 1 до 30; у каждого узла адрес, имя и время. Имя — обратный запрос через системный резолвер: он идёт после того, как узел показан, ждёт не больше 2,5 с и отключается флажком. Останавливается на цели или после восьми молчащих узлов подряд | Компьютер, Android, iOS |
| Сканер портов | TCP-соединения со списком или диапазоном портов одного хоста (`22,80,443`, `1-1024`), по умолчанию 64 одновременно и 800 мс на каждое; порт, который не соединился, показан как закрытый или фильтруемый | Компьютер, Android, iOS |
| Сканер сети | Проверяет диапазон: `192.168.1.0/24`, `192.168.1.10-100`, `192.168.1.10-192.168.1.99` или адрес с маской, не больше 4096 адресов (адрес сети и broadcast подсети не проверяются). Начинает с /24 этого устройства, а если сетей несколько, предлагает список. На каждый адрес идёт эхо-запрос (по 48 адресов одновременно) и TCP-соединения с портами 22, 53, 80, 139, 443, 445, 5000, 8080, 8291 и 62078; узел, который ответил на что-либо из этого, попадает в список с именем, MAC-адресом, производителем, временем ответа и открытыми портами. MAC-адреса берутся из таблицы ARP этого устройства; узел, который есть в таблице, но не ответил ни на одну проверку, тоже показан. iOS и Android 10 и новее закрывают таблицу от приложений, и там в списке нет колонок MAC-адреса и производителя | Компьютер, Android, iOS |
| DNS-запрос | A, AAAA, MX, NS, TXT, CNAME, PTR, SOA, SRV и CAA по UDP у Cloudflare, Google, Quad9, Яндекса или у сервера, который вы впишете; обрезанный ответ запрашивается повторно по TCP. IP-адрес ищется как PTR | Компьютер, Android, iOS |
| Whois | Две вкладки. RDAP спрашивает реестр по HTTPS о домене, IP-адресе, сети в записи CIDR или номере AS и показывает статус, даты, DNS-серверы, регистратора и контакты, которые реестр открывает, строками; исходный JSON включается одной галочкой. Сервер берётся из файлов IANA на data.iana.org, если в них его нет, вместо него спрашивается rdap.org. Порт 43: спрашивает whois.iana.org, идёт по его ссылке в реестр и, если реестр назовёт регистратора, к нему; сервер, который отказал, оставляет на экране то, что успел прислать, и назван под текстом | RDAP: компьютер, Android; порт 43: компьютер, Android, iOS |
| Сведения об IP | Адрес, имя хоста или пусто (ваш публичный адрес). Показывает адреса, в которые превращается имя, обратное имя, AS, префикс, страну и реестр из DNS-сервиса Team Cymru, запись о сети из RDAP с контактом для жалоб, а также местоположение и провайдера с ipwho.is (с ipapi.co, если тот не ответил); для вашего адреса ещё и адрес другого семейства с ipify. Каждый блок называет хост, к которому обращался; сбой одного блока не мешает остальным | Компьютер, Android |
| Тест скорости | Задержка (медиана и джиттер по пяти запросам), приём и отдача по четырём параллельным соединениям с speed.cloudflare.com или с другим сервером, у которого те же /meta, /__down и /__up; первые полсекунды фазы не считаются, следующие 8 с считаются, цифра на экране меняется по ходу. «Стоп» обрывает соединения | Компьютер, Android |
| Wake-on-LAN | Отправляет magic-пакет на MAC-адрес широковещательным UDP (по умолчанию 255.255.255.255, порт 9) | Компьютер, Android, iOS с разрешением multicast |
| Калькулятор подсетей | Для IPv4 — сеть, маска, wildcard, broadcast, первый и последний хост, число хостов, класс и двоичная запись; для IPv6 — сеть, первый и последний адрес и их число. Диапазон (`192.168.1.10-192.168.5.110` или `192.168.1.10-100`, где число — последний октет) даёт первый и последний адрес, их число, наименьший набор блоков CIDR, который покрывает диапазон точно, и наименьшую сеть вокруг него | Везде |
| Разбиение подсетей | Три режима. «Равные» делит сеть (или диапазон, который ровно одна сеть) на части по их числу (округляется вверх до степени двойки) или по префиксу; в таблице до 1024 частей. VLSM даёт каждому числу хостов свой блок, от большего к меньшему, внутри сети или диапазона; блок не меньше /30. «Суммаризация» сводит список сетей и диапазонов, по одному в строке или через запятую, в наименьший набор блоков CIDR | Везде |
| Время передачи | По двум из трёх величин — размер, скорость, время — считает третью: размеры от Б до ТиБ (десятичные и двоичные), скорости от бит/с до ГБ/с, время в часах, минутах и секундах. Накладные расходы в процентах — доля скорости, которая не несёт данных. Для известного размера под результатом показано время при 10 Мбит/с, 100 Мбит/с и 1 Гбит/с | Везде |
| Справочник портов | 109 известных портов TCP и UDP с протоколом, сервисом и коротким описанием на языке интерфейса. Фильтр понимает начало номера, часть названия сервиса, протокол или слово из описания. Сканер портов называет открытые порты по тому же списку | Везде |
| Производитель по MAC | Ищет производителя во встроенном реестре IEEE (58 623 блока на 2026-09-25); выигрывает самый длинный префикс | Везде |

Браузер не открывает сокеты, поэтому на странице есть калькулятор, разбиение подсетей, справочник портов, время передачи и поиск по MAC. На iOS эхо-запросы пинга, трассировки и сканера сети идут через ICMP-сокет, которому не нужны права.

RDAP, сведения об IP и тест скорости шлют запросы на сторонние хосты, которые перечислены строкой под их формой. Им нужен HTTPS с проверкой сертификата системой, он есть на компьютере и в Android; на iOS из трёх остаётся только whois по порту 43, в браузере ни одного.

Сканирование шлёт много пакетов, поэтому запускайте его только в сетях, которыми вы управляете. На Android 10 и новее таблица ARP закрыта для приложений: MAC-адресов там не будет, а узлы, которые отвечают только на ARP, не найдутся. У MAC-адреса с битом «назначен локально», которым телефоны прячут устройство, нет производителя, он помечен как «случайный или локальный».

## Внешний вид

В настройках в списке «Тема» три темы. Modern стоит по умолчанию: плоские элементы и раскладка WinBox 4. Legacy повторяет WinBox 3 с объёмными кнопками и вкладками в рамке и остаётся светлым, пока в «Вид» не выбран тёмный. Material сделан по Material Design 3: кнопки-капсулы, скруглённые окна с тонкой рамкой, тональное выделение текущего пункта, заголовок активного окна в оттенке акцента. Размеры рассчитаны на мышь: строки таблиц 26 dp против 24 у Modern, поля и заголовки окон 32 dp; на телефоне любая тема вырастает до 40 dp под палец. «Строки таблиц» в тех же настройках прибавляют каждой строке таблицы до 8 dp или убирают 2. «Комментарии в таблицах» ставят комментарий строки над ней, в столбец или убирают совсем; таблица, у которой в меню комментариев выбран другой режим, держит его, пока в меню не выбран режим из настроек. «Цвет» выбирает один из восьми акцентов, и Material строит из него и светлую, и тёмную палитру. На Android 12 и новее «Цвета системы» вместо этого берут палитру, которую Android строит по обоям. «Вид» выбирает между светлым, тёмным и настройкой системы; Modern и Material повторяют систему, пока это не изменено.

## Если что-то не получается

| Что вы видите | В чём дело | Что делать |
| --- | --- | --- |
| «… не принимает подключения на порт N: сервис выключен или порт закрыт» | служба на роутере выключена или порт закрыт файрволом | включите службу (на RouterOS, например, `/ip service enable api`) или выберите другой протокол; серым в списке помечены порты, которые не ответили |
| «… не отвечает» | неверный адрес, нет маршрута или файрвол молча отбрасывает пакеты | проверьте адрес, пропингуйте роутер, убедитесь, что вы в той же сети; если роутер за другим роутером, используйте поле «Через роутер» |
| «Не удалось найти …» | имя не удаётся преобразовать в адрес | впишите IP-адрес |
| «Роутер не принял вход: …» | неверный логин или пароль, либо у пользователя нет прав на эту службу | проверьте их и, на RouterOS, группу пользователя |
| «… и NetworkHelm не договорились о TLS …» | на RouterOS включён API-SSL, но у службы нет сертификата | выберите «API (8728)», подключитесь и в окне «Подготовить роутер» выпустите сертификат |
| «… не ответил по SNMP» | community неверная или у неё нет права чтения (свитч считает такой запрос «illegal operation for community name supplied»), агент выключен или закрыт UDP 161 | проверьте community на агенте: она должна существовать с правом чтения и пускать ваш адрес; SNMP v2c должен быть включён |
| «the SNMP agent answered notWritable for …» (или noAccess, readOnly, authorizationError) | объект на этом агенте только для чтения, или у community или пользователя нет права его писать | возьмите community или пользователя с правом записи и представлением, в которое входит объект |
| «the SNMP agent answered inconsistentValue for …» (или wrongValue, wrongLength, noCreation) | агент не принимает это значение или эту строку: у новой строки не заполнена обязательная колонка, индекс занят, значение вне допустимого диапазона | заполните остальные колонки строки, возьмите другой индекс, проверьте допустимые значения в документации устройства |
| «Android не пускает NetworkHelm в локальную сеть» | не выдано разрешение | в настройках приложения Android разрешите «Устройства поблизости» |
| «Соединение потеряно после отправки команды. …» | связь пропала в момент правки | сначала проверьте роутер: команда могла выполниться, и повтор сделает её дважды |
| «Соединение с роутером потеряно, переподключение…» | связь пропала или роутер перезагрузился; на телефоне система ещё и закрывает соединения приложения в фоне | подождите: сеанс вернётся сам, открытые формы сохранят введённое; на телефоне после возврата в приложение это занимает несколько секунд |
| «Загрузка… 2187 из 34998» внизу списка | по TCP 8291, SSH и REST таблица больше 2 000 строк идёт порциями, чтобы роутеру не пришлось держать её в памяти целиком; в локальной сети 30 000 строк занимают около 10 секунд по REST и 40 по TCP 8291 | подождите: список готов, когда счётчик сменится числом строк |
| «Не загружено» и кнопка «Повторить» под списком | строки не пришли, причина написана рядом с кнопкой | нажмите «Повторить» или F5 |
| Роутер перестал отвечать сразу после ввода адреса | его защита от подбора паролей сочла проверку портов попыткой входа | дождитесь конца блокировки и выключите проверку в «Настройках» |
| «Браузер заблокировал запрос …» | страница в браузере умеет только HTTP, а RouterOS не шлёт заголовки CORS | откройте приложение через шлюз или подключайтесь приложением |
| Программа не запускается | на компьютере причина записана в файл `NetworkHelm-startup-error.log` во временной папке | возьмите файл (`%TEMP%` в Windows, `/tmp` в Linux) и приложите к обращению вместе с версией системы |

Остальное можно спросить в [трекере задач](https://github.com/vasmarfas/networkhelm/issues). Адреса, пароли и ключи в обращения не вставляйте.

## Где лежат данные

Сохранённые роутеры, настройки и раскладки таблиц программа хранит в своей папке данных. Пароли и ключи, которые вы попросили запомнить, лежат в защищённом хранилище системы: защита данных Windows (DPAPI), связка ключей в macOS и iOS, Secret Service в Linux, Android Keystore в Android. Если системного хранилища нет, программа шифрует их сама, и такая защита слабее. Всё подробно описано в [privacy-policy.md](privacy-policy.md).
